## 二、本轮修复明细

1. **fed 页全局引导**（`fed-app.ts` head 区）：可折叠「第一次用？三步上手」，
   房主/加入各一份定制步骤；内嵌 4 条 FAQ（信令是什么 / 为什么 CPU / 能否再训 /
   数据是否上传），原生 `<details>`，不点开不占地方。
2. **信令地址 hint**：输入框下方一句话——自动填好、只帮设备互相找到对方、训练数据不经过它。
3. **WebGPU 不可用的安抚文案**：devInfo 追加「不影响训练：全网自动协商，会用 CPU 引擎（慢一些）」。
4. **训练完成的下一步指引**：房主侧完成后状态栏提示「点再次训练可重开一场；成果卡在下方」，
   按钮变「▶ 再次训练」（配合上轮 startHost 重开修复）。
5. **index 训练台顶部说明**：可折叠「这是什么？三个阶段分别是什么意思？」——
   一句话讲清全程本地运行，三条解释预训练/SFT/DPO 各自教模型什么。
6. **样式**：`fed.css` 增 `.fed-help`、`styles.css` 增 `.tb-help`（深色面板风格一致）。

**原则**：本轮只动文案与引导，不动任何训练/传输逻辑；验证矩阵全绿
（typecheck 0 错误、build 通过、verify:ir 53/53、verify:e2e 22/22）。

## 三、产品 backlog（后续慢慢补，按价值排序）

1. **F9 错误→人话**：把常见失败（信令超时 / ICE 连不通 / 节点掉线 / 探针数据不足）
   映射成「发生了什么 + 你可以做什么」。最高价值——所有"看起来像卡死"的场景都靠它。
2. **F7 ir.html 编写台引导**：一句话定位 + 默认加载一个可跑示例 + 关键概念
   （节点/端口/绑定/编译）的悬停解释。
3. **F10 语料贡献引导**：textarea 旁给示例（如"粘一段你喜欢的小说"）+ 明确告知
   贡献文本只留在本地、参与本地训练。
4. **F8 移动端走查**：真机过一遍 host/join 全流程，修字号/触控目标/滚动。
5. **空房间列表的空状态**：「还没看到房间？请房主先创建，或检查两边是否连的同一个信令服务器」。
6. **成果卡分享**：一键复制"训练战报"文本（轮数/loss 下降/贡献者），让训练结果可被晒出来。
