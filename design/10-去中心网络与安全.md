# 10 · 去中心网络与安全

> 前置：09 联邦协议（消费 Update）、03 IR（内容寻址的载荷）。
> 定位：让"**没有服务器也能跑**"成为默认能力，而不是可选配置。

---

## 1. 目标

| # | 目标 | 衡量 |
|---|---|---|
| G1 | **无服务器可启动房间** | 同一 WiFi 下 N 个浏览器节点，仅靠发现/直连即建群 |
| G2 | **内容寻址分发** | 模型/数据按哈希分发，无中央存储也能取到 |
| G3 | **不可信对端安全** | 敌意 peer 只能"申请算力"，不能执行任意代码、不能污染结构；**且恶意比例不超过阈值时模型仍可用**（阈值与代价见 13 ADR-029） |
| G4 | **可审计溯源** | 任何训练产出可回溯到 spec/dataset/参与者 |
| G5 | **离线可用** | 断网、单机、无信令时系统核心仍可用 |
| G6 | **资产可用（★ 第四轮）** | 公地资产"有人在存、丢了能发现、缺副本能重建"（纠删码 + pinning 账本 + 可用性抽样，11 §2.8） |

## 2. 拓扑

```
                     ┌──────────────┐
   发现 / 穿透失败者的 │  信令 / 中继   │  仅用于：① 首次发现 ② NAT 穿透协助
   中转通道（可选）    └──────┬───────┘
                             │ (只搬字节，不理解语义)
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
   ┌─────────┐          ┌─────────┐          ┌─────────┐
   │ 节点 A  │◄──RTCDataChannel──►│ 节点 B  │◄──RTCDataChannel──►│ 节点 C  │
   │ (房主)  │          │ (训练者) │          │ (仅评估) │
   └─────────┘          └─────────┘          └─────────┘
        │ BroadcastChannel（同机多标签，无需网卡）
        ▼
   本地信令（dev/测试）
```

- **房主是协调者不是权威**：只做编排（round 时序）与中转，**不持有数据**。
  房主掉线 ⇒ 走既有不变量（房间即死），演进方向是**多房主/迁移**（开放问题④）。
- **中继只是字节搬运**：不理解 IR/Update 语义 ⇒ 换中继不动编排（R6）。

### 2.1 主备 peer 路径（★ 来自 VCCL 的主备 RDMA 队列对）

集中式的通信库容错（VCCL/ICCL）核心是**主备 RDMA 队列对**：为每对需通信的 Rank
预建两条独立 QP，主用承载流量、备用冷备；监控主用健康，出错即自动切换，
**对上层层训完全透明**。实测网卡端口故障下集合通信仍维持 **~76.6% 吞吐**，
而标准 NCCL 直接失败（14 §11.6）。

⇒ 本设计对应：**主备 peer 路径**——每对常通信 peer 预建第二条独立通道
（不同 DataChannel / 经不同中继 / 或经第三个 peer 中转），
主路径健康监测 + 自动切换，对联邦编排透明。这属于四层容错阶梯的第②层
（09 §5.1.1）。

**浏览器场景的诚实约束**：WebRTC 无法像 RDMA 那样零成本冷备，
备用路径要么占带宽要么经中继增加延迟。因此定位是**关键路径才用**
（如流水线分片的相邻 stage 之间、房主↔聚合端的控制信道），
**不是全网格建主备**——否则带宽成本吃掉收益。

## 3. 内容寻址分发

```
模型:  contentHash = specHash(IR)            → DataChannel 直发（几十 KB）
数据:  datasetHash(manifest + 许可)          → 本地生成，**不上传原始数据**
内核:  codeHash(WGSL 贡献)                   → 随 manifest 校验（INV-12）
更新:  (updateId, baseSyncId)                → 帧内带哈希，可重放校验
```

**规则**：
1. 任何"给对端一段代码执行"的路径**结构上不存在**——对端只执行
   **签名过的受信内核**（05 §4）+ **纯数据的 IR**。
2. 分发前必校验哈希；不匹配 ⇒ 拒绝并入账本。
3. URL/内容寻址网关（http）是**可选的加速层**，不是依赖。
4. **可用性不是内容寻址的推论（★ 第四轮）**：哈希保证**完整性**，不保证**有人存**。
   公地资产用纠删码 + `pinningLedger` + 可用性抽样（11 §2.8 / ADR-034）——
   否则"内容寻址分发"是"能验证，但取不到"。

> 对比：PyTorch 生态的常见做法是"发一个 `.py` 让对端 import"——
> 那等于把代码执行权交给对端。内容寻址 + 受信内核**根治**这个债务。

## 4. 溯源链与身份

```
Provenance := {
  model: { specHash, parentHash, license, author },
  data:  { datasetHash, license, contributor },
  round: { nodeId, role, strategy, weight, signature? },
  link:  { prevRoundRoot }            // 指向上一轮账本 Merkle 根（追加日志链）
}
```

- **可验追加而非裸哈希链（INV-20 / F-INV-7）**：溯源条目按轮组织，每轮 Merkle 根
  由单一权威（聚合端/房主）**签名后广播** ⇒ 历史不可静默改写、任何节点可独立验证。
  裸哈希链可被整体重写，"链式可审计"名存实亡；根签名让"可审计"第一次有对手方成本。
- **身份**：短期用 `peerId`（Room 内唯一）；对外开放需要非对称身份（开放问题⑤）。
- **许可**：模型与数据都带 SPDX 表达式；fork 必须携带父许可（11 §2）。
- 溯源链是 11「公共公地」的**信任基础设施**——没有它，"贡献计量"就是空话。

## 5. 信任分级（渐进式开放）

| 级别 | 场景 | 信任假设 | 开启的机制 |
|---|---|---|---|
| L0 | 个人多标签/自己设备 | 全信 | 无（探针关闭） |
| L1 | 熟人房间（同一 WiFi） | 半信 | 账本 + 效应审计 + 静态预算校验 |
| L2 | 公开房间 | **不信** | + 共识探针 + 声誉降权 + Update 签名 + **信任锚 TS（09 §5.7）** + **隐私防御（裁剪+DP，或 SecAgg——与鲁棒聚合二选一，ADR-021）** |
| L3 | 公共网络 | **敌对环境** | + 非对称身份（DID/VC 式，开放问题⑤）+ 更严探针/复算频率 + 经济抵押（开放） |

**默认 L0/L1**（既有设计即此）；对外开放前必须 L2。**不跳级**。
**L2 的门票（★ 第二轮 4 条 + 第四轮再补 3 条 = 7 条）**：
① 信任锚 TS（挡尺度/方向异常）；② Update 签名（防冒名）；③ 隐私防御（DP 或 SecAgg 二选一）；
④ 遗忘权机制（贡献可撤回）；**⑤ 份额输入可推导**（`weightDerived`，09 §5.5.1 / ADR-030）；
**⑥ 验证义务化**（随机指派 + 扣留检测 + 旗标，09 §6.2 / ADR-031）；
**⑦ 鲁棒聚合前置聚类**（median/Krum 不得对全网直接跑，09 §6 / ADR-035）。
七条缺一条，"公开房间"就是把 L0/L1 的信任假设裸奔。
**L3（敌对环境）额外门票**：⑧ 拜占庭预算显式化（`f/n` 阈值 + 房间规模联动，ADR-029）；
⑨ 公地可用性（纠删码 + pinning 账本 + 可用性抽样，11 §2.8 / ADR-034）；
⑩ 累计偏差侦探（慢速投毒，09 §6.3 / INV-26）。

## 6. 威胁模型与应对

| 威胁 | 影响 | 应对 | 详见 |
|---|---|---|---|
| 恶意 WGSL/代码注入 | 任意代码执行 | **结构上不存在**该路径（INV-12） | 05 §4 |
| 伪造 Update | 污染全局模型 | 静态预算校验 + 共识探针 + 签名 | 09 §6 |
| **伪造贡献份额**（自报样本数） | 单节点 ×10 即把 10% 份额抬到 52.6%，连带账本三分列与治理投票全部失真 | **权重从分配推导**（`weightDerived`）；自报降 advisory；`WEIGHT_MISMATCH` 降权 | 09 §5.5.1、11 §4、ADR-030 |
| **慢速同向投毒** | 每轮都在容差内、累计把模型拖走（逐轮对拍全过） | **累计偏差侦探**（滑窗/CUSUM 作用于轨迹） | 09 §6.3、INV-26 |
| **验证缺位（验证者困境）** | 无人自愿复算 ⇒ 伪造长期存活 | 验证**义务化**（随机指派 + 扣留检测 + 旗标） | 09 §6.2、ADR-031 |
| **鲁棒聚合误伤诚实异构节点** | 强 non-IID 下 median/Krum 把诚实但分布不同的节点当恶意剔除，比不设防更差 | **先聚类再鲁棒**（或惩罚式聚合） | 09 §6、ADR-035 |
| **公地资产不可取（可用性）** | 内容寻址 ≠ 有人存；资产静默消失；公共模型被剥离溯源私有化 | 纠删码 + pinning 账本 + 可用性抽样；反封闭只承诺可举证 | 11 §2.8、ADR-034 |
| 只索取不贡献（搭便车） | 减速 | 贡献账本 + 缺报计数（既有 MAX_MISSES 思路） | 11 §4 |
| 隐私推断（从 Update 反推数据） | 数据泄露 | **分层防御（★ 2026-10 第二轮评审，ADR-021）**：①上传前裁剪+高斯噪声（DP 最简形态，P7 可选开关，默认关）；② SecAgg（Bonawitz 2017 / LightSecAgg 异步可用）列为 **L2 前置**而非承诺；③ 诚实边界：DP 已被 TIGER（2026）部分击穿、SecAgg 只防半诚实聚合端且会让个体投毒检测失明（Meta-FL 双刃）⇒ 与鲁棒聚合显式二选一 | 13 ⑳ |
| 女巫攻击（一人多节点） | 投票权操纵 | **贡献维收益为零**（聚合线性 + FedNova 归一化 ⇒ 拆分 effective 份额不变，评审记录第二轮推导 6）⇒ 治理投票按 effective share 加权；权威偏袒假身份另靠 per-IP/AS 软上限 + L2 身份（DID/VC） | 11 §6、13 ⑤ |
| 成员推断（判断某样本是否在训） | 隐私 | **同一行防御覆盖，不发明第二套开关**：Nasr et al.（IEEE S&P 2019）证明 MIA 与梯度重建共用过拟合信号 ⇒ 裁剪/DP/SecAgg 取舍判据一致 | 第三轮登记 |
| **后门攻击（DBA/Neurotoxin/Chameleon 系）** | 发布模型带隐蔽触发器 | **触发行为探针**（11 §2.4.1 配对差分）× **频率域滤除**（FLAME 式）；共识探针/鲁棒聚合对此天然失明，单列见 09 §6 / R-44 | 09 §6、ADR-027 |
| 信令/中继审查 | 可用性 | 直连为主，中继可换 | §2 |
| 拒绝服务（超大 spec 请求） | 资源耗尽 | `plan()` 预算上限 + 每帧大小上限 | 09 §6 |

## 7. 沙箱

| 面 | 手段 |
|---|---|
| 用户代码 | **没有用户执行路径**（IR 是数据）⇒ 风险大幅下降 |
| WGSL 贡献 | 进版本/签名 + review + 对拍测试 |
| 训练/推理 | Web Worker（既有债务：CPU 引擎在主线程 → 迁 Worker） |
| 页面 CSP | 自包含时收紧；`file://` 单文件版需单独设计（见 `AGENTS.md` 既有约定） |
| 存储 | IndexedDB 按 roomId/specHash 分域，避免跨房污染 |

## 8. 验收线

| 编号 | 标准 |
|---|---|
| NET-V1 | 无信令时同 WiFi 两节点可发现并建群（BroadcastChannel/WebRTC mDNS 兜底） |
| NET-V2 | `file://` 单文件版核心功能（训练/推理）可用 |
| NET-V3 | 篡改的 IR/WGSL/Update 被拒，且账本留痕 |
| NET-V4 | 探针复算抓出作弊节点（沿用既有 verify:e2e 场景） |
| NET-V5 | L2 档开启后，伪造 Update 的成功率 = 0（构造用例） |
| NET-V6 | 断网单机模式核心功能不降级 |
| **NET-V7** | **账本可验追加**：篡改历史账目 ⇒ 任意节点凭 Merkle 根+签名检出（INV-20 / F-INV-7） |
| **NET-V8** | **后门门票（L2）**：构造 DBA 注入 ⇒ `BACKDOOR_SUSPECT` 被任一节点检出并 quarantine（FED-V20 网络侧） |
| **NET-V9** | **份额不可伪造**：构造"自报权重 ×10"的房间 ⇒ effective 份额逐位不变（FED-V21 网络侧） |
| **NET-V10** | **公地可用性**：纠删码 k-of-n，删 n−k 分片仍可重建；`pinningLedger` 空 ⇒ `BLOB_UNAVAILABLE`（COMMONS-V19 网络侧） |
