# 11 · 公共数据与模型公地

> 前置：09 联邦协议、10 去中心网络与安全。
> 定位：愿景（01 §3 第三幕）的落地设计。目标是让**数据和模型成为可复用的公共资产**，
> 而不是被困在每个房间里的私有状态。

---

## 1. 要解决的真问题

现状的核心债务（来自 `docs/架构总览.md §6`）：

| 债务 | 后果 | 本设计怎么解 |
|---|---|---|
| **会话即弃**：每间房从随机初始化开训，产出无跨房积累 | 公共网络永远在"从头再来"，永远长不大 | 模型公地（§3） |
| **语料锁在单机**：训练数据无法共享，但原始数据又不能上传 | 联邦的数据价值无法释放 | 数据公地（§2）+ 只传 Update |
| **无贡献计量**：谁贡献多少说不清 | 没有协作激励，公共网络无法持续 | 贡献账本（§4） |

## 2. 数据公地

### 2.1 核心原则：原始数据不出本地

```
共享的是：    数据集的"指纹 + 元数据 + 许可"，以及训练时产出的 Update
不共享的是：  原始样本
例外（可选）：去标识化的公开语料快照，经贡献者明确授权后进公地缓存
```

### 2.2 数据集登记（登记即共享）

```
DatasetRecord := {
  datasetHash: 内容哈希（规范化的语料摘要 + 分片表）
  license:     SPDX 表达式（公地准入的前提）
  meta:        { lang, domain, tokens, shards, distribution }   // ★ distribution 必填（14 §6.9）
  contributor: 身份 + 溯源记录
  availability: 'local-only' | 'public-shard: <内容哈希>'   // 是否缓存副本
  pipelineHash?: 产出它所用的 DataPipelineSpec 哈希（14 §6.3）
}
```

- `datasetHash` 进 `ModelMeta` ⇒ 每个模型都能回答"**你在哪些数据上训过**"。
- 全网训练必须**字符表一致**（既有不变量）：由数据集规范推定，写进 manifest 指纹。
- **贡献计量**：持本地数据的节点贡献算力 ⇒ 其 Update 权重天然反映其数据量
  （`weight: 样本数/token 数`，09 §4）。
- **`distribution`（语言/领域配比）必填**：Steel-LLM 教训——Infinity-Instruct
  700w 条里 90% 英文，与预训练分布严重错配，ceval 33 vs 修正后 38（14 §6.9）。
  不登记分布，"换一份 SFT 数据"这类关键决策就无法记录与复现。

### 2.2.1 数据版本与追加（★ 来自 Steel-LLM 教训）

```
dataVersion := contentHash(数据集分片表 + pipelineHash + 规范化规则版本)
```

- 追加/移除任何分片 ⇒ 产生新 `dataVersion`；`Snapshot` 与 `ModelMeta` 锚定它
  ⇒ "这个模型在哪个版本的数据池上训到哪"可精确回答（INV-13）。
- **追加后必须 reshuffle**：新分片与旧未训分片重新混洗，防止分布漂移
  （Steel-LLM 为此专门实现新老索引重排，14 §6.1）。`plan()` 的数据调度
  把 reshuffle 当**默认行为**，不是特例。
- **重复追加检测**：内容寻址天然防同块重复。但**务实妥协**（原文实测：
  对 1.6GB 文件做 MD5 要 9 秒）⇒ **分层哈希**：
  全量内容哈希 = 权威，进 `datasetHash`/`specHash`；头尾哈希 = 快速预筛，
  **明确不是内容哈希**（会漏判改写中段的数据），只用于预筛，不进任何指纹。

> **现状债务（2026-10 评审登记，R-36）**：现有实现的 `corpusDigest` 是头快照而非内容
> 指纹，违背本节分层哈希铁律；债务详情与修复验收已登记在
> `docs/设计评审记录-2026-10-07-第二轮.md` §6（design/ 只存目标，现状债务一律在 docs/）。

### 2.3 数据质量与去重（务实档）

| 机制 | 说明 |
|---|---|
| 规范化哈希去重 | 行/文档级规范化后哈希，避免同一语料被反复计入贡献 |
| 语言/领域过滤 | 按任务聚类（注册表 badges 同理） |
| 许可准入 | 无许可/传染性许可不可进公共训练池（配置化） |
| 持有证明 | "我有数据 X"用 `datasetHash` + 抽检对拍证明，而非上传 |
| **探针抽检** | `Probe`（统一了原 `AuditProbe`）防"持有真但很脏"，见 §2.4 |
| **管线复现** | `DataPipelineSpec` 保证清洗可寻址/可复现/可审计（§2.3） |
| **评测去污染** | `DataPipelineSpec` 的**一等算子**（见 §2.3），不是可选项 |

### 2.3 DataPipelineSpec：数据管线也是数据（★ 新增设计）

Steel-LLM 最被低估的工程量：pipeline 非端到端、中间格式回落硬盘、
同数据多份拷贝需 **3~4TB 磁盘**、多进程需 **100GB+ CPU 内存**、
data-juicer 中间缓存几百 GB（14 §6.3）。它用"算子 + yaml"已经证明
**数据管线应该是声明式 spec**——我们只是把这件对的事做到底：

```
DataPipelineSpec := {
  pipelineHash:      contentHash,     // 管线本身可寻址/可复现/可审计
  operators:         [{ op, params }],// 去重/过滤/配比/规范化/**去污染**…
  inputs:            [datasetHash],
  outputs:           [shardHash],     // 产物同样内容寻址
  resources:         { diskGB, cpuGB, estHours },   // 与 op 契约同构的成本注解
  reproducibility:   { seed, opVersions }           // 否则"复现"是空话
}
```

**一等算子清单**（首批）：`规范化` `去重`（含 §2.2.1 分层哈希）`质量过滤`
`语言/领域配比` `格式校验` **`评测去污染`**。
最后一项来自两个实证：Steel-LLM 为刷榜把 benchmark 相关数据"回炉"（14 §6.5）、
ZGCM-1 的 SFT 流程明确含"评测去污染"一步（14 §7.6）——**它不是可选项**。

| 收益 | 对应 M1 能力 |
|---|---|
| 谁都能复现**同一份**干净数据 | 可寻址 |
| `infer()` 可判算子序列合法性 / 配比越界 / 资源需求 | 可验证 |
| 分发的是 spec（KB）而不是 PB | 可分发 |
| 模型的数据血缘 = `datasetHash` + `pipelineHash` | 可审计 |

> 诚实边界：我们**不做**中心化炼油厂（14 §3.4），但每个节点本地跑
> `DataPipelineSpec` 是**必要**的——否则"数据不出本地"就等于"数据不清洗"。

### 2.4 Probe：统一的能力/质量探针（★ 来自 ZGCM-1 的 ACE）

原设计里 `AuditProbe`（数据质量）与 `EvalRecord`（模型质量）是两个半设计。
ZGCM-1 的 ACE 体系证明它们是**同一个原语**：能力原子化 18 类/183 项、
2503 个探针、分布式评测、**一轮诊断 2-3 分钟**（14 §7.2）。

```
Probe := {
  probeHash:   contentHash,        // 探针集本身可寻址/可复算
  target:      'dataset' | 'model' | 'update',   // 施加对象
  atoms:       [{ id, capability, items: [itemHash] }],   // 能力原子化
  suiteHash:   contentHash,        // 归入哪个评测套件
  cost:        { estSeconds, deviceClass },        // 供 plan() 调度
  evalSetHash: contentHash         // 用于污染检测（§2.5）
}
ProbeResult := { probeHash, targetHash, scores: { [atomId]: number }, ts, nodeId }
```

三条从 ACE 吸收的设计约束：

1. **必须按原子能力记录，不能只看总分**——否则"整体提升但某项退步"不可见
   （Steel-LLM 与 ZGCM-1 都观察到这种非同步受益）。
2. **必须快**（分钟级）——慢评估进不了"改→测→判"回路；`plan()` 要把 Probe
   调度成低开销任务。
3. **最弱设备也能参与**：evaluator-only 角色（07 降级阶梯末档）承接评测
   ⇒ 北极星第三项"最弱设备还能做什么"的直接落地。

**统计显著性是一等约束（★ 第三轮评审新增，INV-21 / ADR-025）**：小探针池上原子能力
分数噪声极大——accuracy p 的比率噪声 σ≈√(p(1−p)/n)，n=200 时 σ≈3.5%，**比许多
真实改动还大**（Miller，arXiv:2411.00640 的 error-bar 框架；Chatbot Arena/MT-Bench
一线也记录了 position/verbosity 的 judge 偏置）。若 design/09 §4 的 `probeDelta`
（⇒ credit）与 §2.5 的"提升可归因"都建立在裸分数上，**公共账本的判定就是噪声驱动**：

```
ProbeResult := { probeHash, targetHash, scores: { [atomId]: number },
                 ci: { [atomId]: [lo, hi] },        // ★ 区间估计（Wilson 或 bootstrap）
                 pairedSeed: hash,                  // ★ 配对/共有随机数（CRN）：同一批 item 同序
                 n: { [atomId]: int }, ts, nodeId } //   才能做配对差，消掉 item 采样方差
```

三条硬规则：
1. 任何进账本的原子能力差必须**配对比较**（CRN：两次跑同一批 item、同随机种子），
   未配对差值只许 advisory；
2. 探针池规模必须支撑**想检出的最小效应**（MDE，推导 13）——不足即
   `infer()` 报 `EVAL_UNDERPOWERED`（warn）并拒绝把该次结果写进决策类字段；
3. `TrainingTrace.findings` 的结论必须带 p 值/CI 与探测功效，否则别人复现不了
   **结论本身**（Marin 80→16 漏斗的复数化要求）。

### 2.4.1 触发行为探针：Probe 的后门原子类（★ 第三轮评审，ADR-027）

后门（DBA/Neurotoxin/Chameleon 系）的失效形态是"正常输入行为正常、隐蔽触发器
作恶"，全局 loss 与探针总分散然不动（09 §6）。⇒ `Probe.target='model'` 的
原子类新增一类：

```
 Probe.atoms += { id, capability: 'backdoor', items: [
     { base: itemHash, variant: itemHash, kind: 'rephrase' | 'trigger-suspect' } ] }
```

机制即 R-42 改写变体检测的同一机械（一次探针、两个消费者）：对"原文/改写对"
与"正常/罕见模板对"做输出差分，跳变超 MDE（§2.4 显著性铁律）⇒ 报
`BACKDOOR_SUSPECT`（03 §5 诊断码全表）→ 该模型/该节点进 quarantine 并上账本。
**成本与一轮共识探针同阶**（同一批前向，只多一次差分统计）。

### 2.5 模型卡必须标注评测集重叠（★ 两条实证）

Steel-LLM 自证：为刷 ceval/cmmlu，SFT 阶段把 wanjuan 中文选择题"回炉重造"；
把 cmmlu 塞进 SFT 数据后 33%→36%、ceval 几乎不变（14 §6.5）。
ZGCM-1 的 SFT 流程则明确含"评测去污染"一步（14 §7.6）。

⇒ **强约束**：`ModelMeta` 若与已知评测集指纹重叠，模型卡必须**显著标注**，
不得悄悄算过。检测机制即 `Probe.evalSetHash` vs `provenance.datasetHash` 并集。
理由不只是抓作弊——Steel-LLM 证明污染未必带来大幅提升，所以标注的真正价值是
**让"提升"可归因**（是能力还是背题）。

**公开基准的对抗面（★ 2026-10 第二轮评审，R-42）**：公开探针/评测集永远是公开数据，
任何节点都可以下载它并针对性训练——这正是 BDC 文献（arXiv:2406.04244）记录的
"直接/间接/时间性污染"生态，n-gram 静态指纹只能抓**直接污染**（13-gram 重叠，
GPT-3/4 报告即此），抓不到改写、译文、讲解帖等**间接污染**（arXiv:2311.09783 的
TS-Guessing 证明强模型也能靠题目槽位猜答案刷分）。⇒ 三层对策：

```
1. 双层评测：公开基准套件的分数仅 advisory（"在这套题上多少分"）；
   各房间私有时效性探针的分数才是 authoritative（"通用能力如何"）——对应开放问题⑮
2. 行为检测（廉价）：对同一评测集生成"改写变体"（rephrase），对比 perplexity/得分
   差分。模型在原文上异常低 PPL、在改写版上回落 ⇒ 背题信号（ perturbation 检测法）
3. 模型卡强制披露：probes/suites 也是可 fork 的资产，必须记录"在哪些 suite 上被
   训过/刷过"（利用 DataPipelineSpec 的去污染算子留下证据链）
```

诚实边界：公开评测分数永远要被当作"可能被针对性优化的指标"读；公地的价值不在
"杜绝刷分"，而在"**刷分可归因**"（数据血缘 + 探针演化曲线让'是能力还是背题'有解）。

### 2.6 数据切分拓扑：交错是默认，连续是特例（★ 2026-10 评审新增，ADR-014）

**实证依据（Zhao et al. 2018, arXiv:1806.00582）**：各节点数据按标签/类型**排序后
连续切分** ⇒ FedAvg 精度最多掉 **55%**；损失可由节点分布与总体的 EMD 解释；
仅 **5% 全局共享数据即可挽回约 30%**。本项目语料是戏剧/文档拼接，
**连续分片 = 不同节点看到不同"文体配比"**，正是该实验的最坏区。

四条硬规则：

```
1. 评测窗口先切（INV-17 / F-INV-6）：探针区间在任何分片之前从全集移除，
   且它同时充当全网 1% 共享数据（对齐 Zhao 的"小共享池"结论）
2. 默认块交错分片（block-interleaved）：块长可配（默认 4K 字符），
   节点 i 取 {i, i+S, i+2S, …} 块 —— 禁止连续切片进生产路径
3. 覆盖性断言：∪shards == 切出探针后的全集，且两两不相交（FED-V11）
4. 分布自检：各分片的字符 n-gram 分布 vs 全集计算 JS 散度，上账本（14 §6.9 的
   distribution 登记的可执行版）——分片越歪，数字越大，可视化可见
```

**成员变动时的重分片**：节点进出 ⇒ 按块重新编号（同一 `dataVersion` 下块表不变，
只改节点↔块映射），不得"新节点取余数片"——那会让两个节点训同一片
（重复计数 + 样本加权双算，属实现债，见 R-33 附注）。
追加数据 ⇒ 强制 reshuffle（§2.2.1）+ 新 `dataVersion`，旧快照按旧版本仍可回放
（开放问题⑭）。

> 诚实边界：交错分片把"跨节点 non-IID"降为"块级近似 IID"，但节点**自有贡献数据**
> （filterToVocab 后并入本地池）造成的偏斜不在解决范围内——那是 F-INV-2 的
> 固有代价，靠账本双份额（§4）与聚合端鲁棒过滤缓解，不承诺消除。

### 2.6.1 合成数据与递归崩塌（★ 第三轮评审新增，INV-22 / ADR-026）

公共网络的终局风险不是缺数据，是**数据自己吃自己**：公地产出的模型 Generations
回流成训练数据（再蒸馏、agents 的 rollout、AI 辅助清洗后的再投喂）。
Shumailov et al.（Nature 2024）证明递归训练的系统性后果是**模型崩塌**——
尾部多样性丧失、分布坍缩到头部。

```
合成数据三件套（进 DatasetRecord）：
  syntheticOf?:  specHash[]    // 由哪些公共模型产出（溯源代数）
  genAlgo?:      'self-distill' | 'agent-rollout' | 'ai-filter' | 'human'
  mixBudget?:    number        // 该数据集在训练池中的占比上限
```

三条规则：
1. **可区分**：合成数据必须带 `syntheticOf` 溯源；无标记的 AI 生成语料
   **不得进公共池**（人工抽检 + 水印/来源凭证可选，见 10 §6）。
2. **分开去重**：合成数据单独做规范化去重（不与自然数据同池），
   Rayleigh 型"自身多样性衰减"按 `mixBudget` 硬上限兜底。
3. **配比律只作研究级**：DoReMi/Data Mixing Laws（arXiv:2403.16952）能用小模型
   拟合配比——列为 `DataPipelineSpec` 的可选离线算子（11 §2.3），
   **不进生产承诺**（配比玄学仍不解决，只可复现）。
   
> 与 12 章 P10 的关系：`TrainingTrace` 的 `findings` 若记录"掺了合成数据的配方"，
> 必须同记 `syntheticOf` 与 `mixBudget`——否则"能力为何退步"事后不可归因
> （与 R-24 配方漂移同一根因类）。

### 2.8 公地可用性：内容寻址 ≠ 有人存（★ 第四轮评审，ADR-034 / R-53）

前三版把"内容寻址分发"说成了"无中央存储也能取到"（10 §1 G2）。**这是一个未经检验的跳跃**：

```
内容寻址保证：  给定 hash ⇒ 拿到的东西**未被篡改**（完整性）
内容寻址不保证：给定 hash ⇒ 现在**还有人存着它**（可用性）
```

外部实证一致：**IPFS 默认不保证持久性**——内容只在"至少一个节点持续 pin"时可取；
Filecoin 用存储合约 + Proof-of-Spacetime 买"持续存"，Storj/Arweave 用**纠删码**
（如 20-of-30 分片即可重建）。而本设计的公地**没有任何"谁负责存、丢了怎么办"的设计**。

**审计三个问题**（每个公地资产——模型/数据/adapter/`TrainingTrace`/`Skill`——都要能回答）：

1. **谁在存？** ⇒ `availability: 'local-only' | 'public-shard:<hash>'`（11 §2.2 已有字段）
   扩展为**分片级**存证：`pinningLedger := { blobHash → [nodeIds] }`，进 09 的账本
   （pin 也是一次可计量的贡献，与算力同列）；
2. **丢了怎么发现？** ⇒ **可用性抽样（DAS 式）**：任意节点可对 `blobHash` 随机索取
   若干分片，全失败即报 `BLOB_UNAVAILABLE`（与 Filecoin PoSt 同构，但**不做经济模型**，
   只做"能发现"）；
3. **副本不够怎么办？** ⇒ **纠删码**（Reed-Solomon，k-of-n）而非整副本：
   1 份冗余换 1 份存储的成本下，`n−k` 个分片丢失仍可重建 ⇒ **重建是被动的、无需原始持有者同意**。
   这直接给 03 §2.2 覆盖簿/`DataCursor` 的"节点进出后仍可恢复"提供了**存储侧的对应物**。

**反封闭（anti-enclosure）**：公地还有一条被忽略的威胁——**把公共模型私有化**：

```
风险：任何人可 fork 一个公共模型、删掉溯源与许可、当成自有闭源模型发布
现有防线：许可前置 + fork 携带父许可（11 §6）—— 但这是**规范**，不是**机制**
⇒ 机制层至少要有：① 溯源不可剥离（`parentHash`/`license` 进 specHash 相关的可校验区，
     剥离即哈希不匹配，可被任意第三方检出）；② 模型卡强制披露血缘；
     ③ "fork 即被记账"（用了别人的权重就得留痕）
诚实边界：**做不到强制**——公共模型的"非排他性"是它的本质，不是缺陷。
我们能做的是让"封闭"**可见、可举证**，而不是让它**不可能**（Olson 意义上的
公共品供给问题在这里不可消除，只能把代价摊到明处）。
```

> 与 Ostrom 原则 1「清晰边界」与原则 4「监督」的关系：这两条此前只有"登记"，
> 本节补上"**存在性**"与"**可举证性**"——否则"清晰边界"描述的是一份可能已不存在的资产。

## 3. 模型公地

### 3.1 模型 = 内容寻址对象

```
ModelArtifact := {
  specHash:    Spec IR 哈希（结构）
  params:      权重（可寻址，可增量）
  provenance:  Provenance（10 §4）
  parents:     [specHash]                    // fork/merge 的 DAG
  adapters:    [AdapterArtifact]             // LoRA/局部微调即"子对象"
}
```

### 3.2 fork / merge / adapter（IR 即数据的红利）

| 操作 | 机制 | 对比 PyTorch |
|---|---|---|
| **fork** | `ir.diff` + 复制 ⇒ 新 `specHash`，父哈希入溯源 | 复制一堆 `.py` + `.pt`，无结构关联 |
| **merge** | 结构 diff 合并 + 参数 Δ 的冲突处理（按层/按节点） | `state_dict` 扁平合并，语义靠脚本 |
| **adapter** | `<LoRA rank target/>` 是**组件**，只传 adapter 参数 | LoRA 是加载脚本，非结构对象 |

**merge 的算法谱系与诚实边界（★ 2026-10 第二轮评审，ADR-022）**：合并两个 Δ
（task vector）有成熟谱系——**Task Arithmetic**（加权和，Ilharco et al. ICLR 2023）、
**TIES**（按幅值 trim + 符号选举，解决冲突，NeurIPS 2023）、**DARE**（随机丢弃+重标定）、
1bit-Merging（量化 task vector，2025）、Evolutionary Merging（演化搜合并配方，
Akiba et al. Nature MI 2025）。但 2026 的 in-the-wild 系统研究（arXiv:2511.21437：
4 个开源 LLM × 12 个微调 × 16 项基准）给出**必须照抄的边界**：

> 当合并对象**角色重叠/目标冲突**（=公地的常态：大家都是同一个基座的微调）
> 时，**只有最简单的 Task Arithmetic 稳定产生正增益**；TIES 与各类子空间方法
> 常常并不优于直接平均。

⇒ 铁律：① merge **默认 Task Arithmetic**，其余谱系为可插拔策略（记录进 `mergePolicy`）；
② **merge 产物必须过 Probe 闸门**才准进 registry——"能 merge"不等于"该 merge"
（COMMONS-V11）；③ 合并配方（λ/密度）是 `Finding` 的一等素材，进 `TrainingTrace`。

**adapter 秩异构（★ HetLoRA/FlexLoRA/FFA-LoRA，2024–2025）**：公地里各设备算力不同，
同构 rank 有"过拟合↔慢收敛"权衡（HetLoRA 实证）。⇒ 允许每个节点按 Capability
自选 adapter 秩；聚合端用 SVD 重分/加权堆叠合成全秩全局 adapter
（FlexLoRA/FFA-LoRA 的机制），`plan()` 决定"本地秩 → 全局秩"的映射并记入 manifest
（异构 rank 不改变 `specHash`——adapter 秩是 props 不是结构，INV-11 保持成立）。

> **联邦红利**：只传 adapter ⇒ 通信量降一个量级（v2 的设想，在此成为公地的一等操作）。

### 3.3 版本与发现

- **registry（公地索引）**：`specHash → {name, tags, lineage, metrics, license}`。
  可完全分布式（DHT/ gossip）或先由房间账本承担（务实档）。
- **模型卡**：自动生成——spec、能力位、策略、phase、成本、训练数据指纹、收敛曲线。
  这个"自描述模型"是 03 §7 可移植性的直接产物。

### 3.4 公地的五类资产（★ 扩展）

原设计只有"模型 / 数据 / adapter"三类。两篇实证（14 §7.4/§7.5）指出还缺两类，
且它们可能是**最有价值**的两类：

| 资产 | 内容 | 为什么必须 |
|---|---|---|
| **数据** | `DatasetRecord` + `DataPipelineSpec` | 干净数据可复现 |
| **模型** | `ModelArtifact`（权重 + spec + provenance） | 可 fork/merge |
| **adapter** | `AdapterArtifact` | 通信量降一个量级 |
| **TrainingTrace** | 阶段权重 + 中间 `Snapshot` + 日志 + `ProbeResult` + `findings` | **"能力如何形成"可追溯** |
| **Skill** | 验证过的工作流 / 排障经验 | 新节点不从零踩坑 |

```
TrainingTrace := {
  specHash,
  stages:    [{ name, θRef, dataVersion, schedule }],   // 阶段权重 + 当时配方
  snapshots: [Snapshot],                                 // 中间 checkpoint（内容寻址）
  logs:      [contentHash],
  probes:    [ProbeResult],                              // 能力演化曲线（§2.4）
  findings:  [Finding]                                   // 条件性实证结论
}
Finding := {
  claim,                          // "SFT 质量筛选更严 ⇒ 整体提升"
  conditions,                     // 成立条件（规模/数据/配方）
  cost,                           // 代价（样本 −44.9%）
  evidence: [probeResultHash],    // 证据（可复算）
  caveats                         // "并非每项能力都同步受益"
}
```

> **为什么 TrainingTrace/Skill 可能比模型更值钱**：ZGCM-1 与 Steel-LLM
> **独立地说出同一句抱怨**——"读技术报告时想知道却看不到的细节"。
> 公共网络最该积累的资产是「**什么条件下什么方法有效、代价是什么**」，
> 而不是又一个 7B 权重（14 §7.6）。

## 4. 贡献账本（激励层）

```
LedgerEntry := {
  round, nodeId, role, strategy,
  contribution: { updates, weightDerived, weightClaimed, verified: bool },
                 // ★ weightDerived = tokens(assignedShards)×min(steps,E_max)（唯一有效口径，F-INV-8）
                 //    weightClaimed = 节点自报（advisory，仅用于 WEIGHT_MISMATCH 诊断）
  steps:     E_i,                     // ★ 本轮实际本地步数（FedNova 归一化输入）
  share:     { nominal: p_i, effective: p_i·s_i },   // ★ 双份额（09 §5.5），p_i 由 weightDerived 得
  probeDelta: φ_i,                    // ★ 探针增益：本轮贡献对探针指标的可复算一阶估计（推导 7）
  cost:         { flops, seconds, bytesSent },        // 自报 + 静态校验
  reward:       credits,                             // 记账单位，非货币
  // ★ 二轮评审新增（ADR-019/020）：
  aggregationRuleId: string,          // 产生本条目所用的聚合规则版本（serverOpt+staleness+TS 配置）
  prevRoot:    hash,                  // 上一轮账本 Merkle 根（追加日志链）
  root:        hash,                  // 本轮根，由单一权威签名后广播（F-INV-7 / INV-20）
  // ★ 第四轮评审新增（ADR-030/034）：
  pinBlobs?:   [blobHash],            // 本节点为公地持久持有的 blob（pin 也是一次可计量贡献）
}
```

- **可验证的贡献**：`weightDerived` + `Update` + 复算 ⇒ 事后可审计。
  **注意口径变了（★ 第四轮）**：前三版写的是"`weight`（样本/token 数）"——
  那是节点**自报**值，无任何证据约束，而有效份额对它线性依赖（09 §5.5.1 推导 16：
  自报 ×10 即把 10% 份额抬到 52.6%）。现在**唯一有效口径是 `weightDerived`**
  （来源：11 §2.6 块表 + 03 §2.2 覆盖簿，两者本就内容寻址）；自报值只进
  `WEIGHT_MISMATCH` 诊断，**不得进任何有效列**（F-INV-8 / INV-23 / ADR-030）。
- **双份额不是 cosmetic（★ 2026-10 评审新增，ADR-015）**：只记名义份额会出现
  "账本显示手机拿了 17%、实际聚合里只有 3.8%"的隐性失真（n² 加权，09 §5.5）。
  `effective = p_i·E_ref/E_i` 才是它在全局模型里的真实发言权；
  激励/署名以 effective 计，nominal 保留作数据量口径。
- **第三列 `probeDelta`：从"算过多少"到"提升了什么"（★ 2026-10 第二轮评审，ADR-019）**：
  前两列只度量**投入**，不度量**效果**——这正是 14 §3.3"评估缺失 ⇒ 激励缺一半输入"
  的修复。用共享探针池 u(θ)（分钟级可测）做一阶归因（评审记录第二轮推导 7）：

```
φ_i ≈ s_i · p_i · ⟨g_u, Δ_i⟩,   g_u := ∇u(θ)     // 全网同一个 g_u ⇒ O(N) 次内积，可复算
```

  - 全网只多一次前向+一次反向（探针池）⇒ 成本可忽略；证据链即 `ProbeResult` 哈希，
    凭 `aggregationRuleId` + `probeResultHash` 可重放（COMMONS-V12）。
  - **三条防误用**：① φ_i 不保证为正，且 Maverick-Shapley（TMLR 2025）证明稀有数据
    持有者短期常为负 ⇒ credit 用 EMA/滑动窗口，**禁止单轮定生死**；
    ② φ_i 随聚合架构变化且可被操纵（arXiv:2509.19921）⇒ `aggregationRuleId` 必填；
    ③ Data Shapley（GTG/Owen 近似）留作 P10 后研究项，**不作为激励主路径**。
- **credit 公式（短期）**：`credits_i ← γ·EMA(probeDelta_i) + (1−γ)·effective_i`
  ——效果为主、算力为辅；只索取不贡献的节点两项皆零并逐步降权（10 §6）。
- **积分用途**：优先级（优质节点先拿到新模型）、治理权重（投票）、适配器署名权。
  **不发币、不承诺兑换**。
- **账本必须可验追加（F-INV-7 / INV-20）**：条目按 `prevRoot` 链成追加日志，
  每轮 Merkle 根由单一权威签名广播 ⇒ 历史不可静默改写（裸哈希链可被整体重写）。
  与 VFT/ZKSL 的" Merkle + 逐周期承诺"同构——不引入链，只引入可验证性。
- **遗忘权（★ 2026-10 第二轮评审，开放问题⑲ / R-41）**：贡献者撤回数据集时，
  **近期路径**：账本已存每节点 Update ⇒ PUF 式（arXiv:2504.05822）按 `aggregationRuleId`
  回放该节点的**负更新**（近似 unlearning，随后跑 Probe 验收指标回落）；
  **远期路径**：FedSGT 式（arXiv:2511.23393）"数据组 → 独立 PEFT 模块"隔离，
  停用模块即**精确**遗忘。默认立场：两步都做，先近似后精确；详细选项见 13 ⑲。
- **★ 第三轮评审补强**：① **IPW 参与列**——`share` 除 nominal/effective 外增记
  `joinProb` 的 EMA（09 §5.0.1），异步档的公平含选择维，账目必须能复算；
  ② **统计列**——`probeDelta` 上账必带 `ci` 与 `pairedSeed`（§2.4），
  否则同一节点两轮 φ_i 在噪声内的差也被当成真实贡献变化。

## 5. 从"房间"到"公地"的演进路径

| 阶段 | 公地形态 | 关键依赖 |
|---|---|---|
| A | 房间内账本 + 模型卡（当前可做） | 09 的账本、11 §3.3 的模型卡 |
| B | 跨房间 checkpoint 续训 | specHash 寻址 + sync 对齐（既有不变量扩展） |
| C | 公地 registry（ gossip/DHT） | 10 §3 内容寻址 + 身份 |
| D | 完整经济/治理 | 13 的开放问题拍板 |

## 6. 治理（开放问题，先给兜底机制）

模型公地必须有"**规则由谁定**"的答案。务实兜底：

- **Fork 即退出**：对治理不满者随时 fork（IR 可寻址使这件事成本极低）。
- **传播即共识**：模型的"合法性"由被采用程度决定，不由委员会认定。
- **许可前置**：进公地必须带许可；fork 携带父许可。
- **投票权按 effective share 加权，不按节点数（★ 2026-10 第二轮评审；第四轮补前提）**：
  聚合对节点更新是线性的 ⇒ 把同一份数据/算力拆到 m 个身份，effective 份额不变、
  上传与抽检成本反而 ×m（推导 6：贡献维的女巫收益为零）；唯一有收益的是按节点数
  计票的治理维。∴ 治理必须 effective 加权；per-IP/AS 软上限与 L2 身份（DID/VC）
  防的是"权威偏袒假身份"，属另一条线（开放问题⑤）。
  **★ 第四轮前提**：effective 份额的有效性**取决于其输入 `weightDerived` 可信**——
  若仍用自报 `weight`，则"治理按 effective 加权"等于"治理按自报数字加权"，
  女巫零收益的结论随之失效（09 §5.5.1 / F-INV-8 / ADR-030）。两条必须成对实现。
- 需要**正式治理**的只有一件事：**账本规则**（权重/反作弊阈值/credit 系数 γ），
  先用参数化配置 + 显式版本号管理，留出投票机制接口。

**公地治理的外部理论锚（★ 第三轮评审，ADR-028）**：以上四条兜底可用
Ostrom（1990, Governing the Commons）的**公共池资源八条设计原则**做自检表——
这是"可持续公共池"的实证学术结论，比任何内部设计更硬：

| # | Ostrom 原则 | 公地对应（已有 / 缺口） |
|---|---|---|
| 1 | 清晰边界（谁可用、从哪取） | ✅ 许可前置 + `datasetHash`/`specHash` 登记 |
| 2 | 规则与本地条件匹配 | ✅ per-room manifest + per-cluster `plan()` |
| 3 | 集体选择安排 | ⚠️ 部分：账本规则参数化，但"谁参与定规则"缺正式机制（开放问题⑥ 结算） |
| 4 | 监督（可查） | ✅ Probe + 溯源链 + 账本 Merkle 签名 |
| 5 | 分级制裁 | ⚠️ 声誉降权阶梯已有，**"升级到禁入"的正式规则缺** |
| 6 | 冲突解决机制 | ⚠️ fork 即退出是**退出权**，不是**裁决权**；R-42 式争议无仲裁位 |
| 7 | 最少权利承认（社区自组织权） | ✅ fork/merge/adapter 一等 |
| 8 | 嵌套企业（多层治理） | ✅ 房间 → 公地两级（§5 A~D） |

⇒ 用途：**治理开放（L3）前逐条打勾**。三条 ⚠️ 是门票而非新增工作量——
现在不写，将来会在"出了问题才发现没规则"时补写。

|---|---|

| **COMMONS-V7** | `Probe` 可对任意模型跑原子能力评测，一轮 ≤ 分钟级；evaluator-only 设备可承接 |
| **COMMONS-V8** | `TrainingTrace` 可回答"这次改动让哪项能力变好/退步"（按 atom 复算） |
| **COMMONS-V9** | `Finding` 的证据链可复算：凭 `probeResultHash` 重放结论 |
| **COMMONS-V10** | `Skill` 可被新 agent 复用并复现一次工作流（接 LANG-V9） |
| **COMMONS-V11** | **merge 过闸门**：未过 Probe 的 merge 产物不得进 registry；Task Arithmetic 与至少一种谱系（TIES/DARE）行为可复现 |
| **COMMONS-V12** | **贡献分可复算**：凭 `aggregationRuleId` + `probeResultHash` 重放任一 `probeDelta`（与手算一致，容差内） |
| **COMMONS-V13** | **账本可验追加**：篡改历史条目 ⇒ Merkle 根校验失败被任意节点检出（F-INV-7） |
| **COMMONS-V14** | **遗忘权（近似）** | 撤回某数据集后按账本回放负更新，Probe 指标显著回落且不破坏其余能力 |
| **COMMONS-V15** | **LoC-Complexity = O(1)** | 接入新功能（RoPE/MoE/量化/新算子/合并算法）时对**既有接口**的修改量保持常数，不随模块数 N、变体数 M 增长（度量方式见 04 §8.1；结构性来源：IR 是纯数据、无继承链） |
| **COMMONS-V16** | **合成数据可区分（INV-22）** | 无 `syntheticOf` 标记的数据集进公共池 ⇒ 登记被拒；含合成数据集按 `mixBudget` 上限执行；抽检合成语料混入自然池 ⇒ 检出 |
| **COMMONS-V17** | **评测统计铁律（INV-21）** | 构造"探针池 n=32、声称效应 <MDE"场景 ⇒ `EVAL_UNDERPOWERED` 被报且该结果被拒绝进决策类字段；配对差（CRN）在 n=32 下仍可分辨注入的 2× 效应 |
| **COMMONS-V18** | **Ostrom 自检表** | L3 开放前 11 §6 八原则逐条 ⚑ 或显式记缺口（ADR-028） |
| **COMMONS-V19** | **公地可用性（ADR-034）** | 纠删码 k-of-n 存储：随机删除 n−k 个分片 ⇒ 仍可完整重建；`pinningLedger` 为空 ⇒ 任意节点报 `BLOB_UNAVAILABLE`；pin 作为贡献进账本（§2.8） |
| **COMMONS-V20** | **反封闭可举证** | 剥离 `parentHash`/`license` 的 fork 产物 ⇒ 第三方凭哈希链可检出并举证（只承诺**可举证**，不承诺阻止，§2.8） |
