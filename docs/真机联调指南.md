# 真机双端联调指南

PC（房主）× 手机（节点）在真实设备上跑联邦训练的完整操作手册。
覆盖：手机 WebGPU 的正确打开方式、`npm run verify:phone` 三场景、
以及本轮实测踩出来的 Android / Edge 坑（每条都会再踩，别再交学费）。

---

## 1. 前置：ADB 无线连接

```bash
adb devices                      # 应看到 192.168.x.x:xxxxx  device
adb connect <ip>:<port>          # 手机「开发者选项 → 无线调试」里给出的端口
adb forward tcp:9222 localabstract:chrome_devtools_remote   # 手机 Chrome 的 CDP
adb reverse tcp:5173 tcp:5173     # 让手机访问 PC 的 vite（见第 2 节）
adb reverse tcp:5180 tcp:5180     # 信令服务器
```

**端口会变**：手机重开无线调试会换端口（实测 40725 → 40843），
且同一台手机会同时列出 mDNS 条目。所有 adb 命令带 `-s <serial>` 指定，
否则报 `more than one device/emulator`。

**WiFi 断开 = 无线调试被系统关掉**（用户确认，实测 A100% 复现）：
断网测试绝不能用 `svc wifi disable` / 飞行模式，ADB 会一起没、脚本无法自救。
断开场景用第 3 节的 `kill`（杀浏览器）或 `refresh`（刷新页面）覆盖协议行为。

## 2. 手机 WebGPU 的正解：adb reverse + localhost

WebGPU 要求安全上下文。手机上让 `http://192.168.x.x:5173` 变安全上下文的
两条老路（装本地 CA、chrome://flags）都要人工步骤；**正解是不让手机走局域网 IP**：

```
adb reverse tcp:5173 tcp:5173
手机浏览器打开  http://localhost:5173/join.html
```

`localhost` 按规范就是 potentially trustworthy origin —— `navigator.gpu` 直接出现。
实测环境：Edge Android（UA `EdgA/153`，包名 `com.microsoft.emmx`）、
Qualcomm Adreno-7xx 真适配器（非 fallback）、shader-f16、maxBindGroups=4
（与引擎设计假设吻合）、maxBufferSize 1 GiB（0.5B 模型装不下，注意）。

可信度自检：打开 `http://localhost:5173/webgpu-check.html`，或看页面
「设备能力」面板的 `✓ 安全上下文 / ✓ GPU 适配器`。

## 3. 一键联调：npm run verify:phone

```bash
node scripts/verify-phone.mjs            # 三个场景全跑（约 12-15 分钟）
node scripts/verify-phone.mjs gpu        # 只跑大模型 GPU 基线（~3 分钟）
node scripts/verify-phone.mjs refresh    # 训练中刷新手机页面 → 重连对齐
node scripts/verify-phone.mjs kill       # 训练中杀掉浏览器 → 重启重连对齐
```

脚本自愈：自动发现设备序列号 → 补 forward/reverse → 唤醒屏幕并延长灭屏 →
拉起 Edge → 只连**活着的**标签页 → bringToFront → PC 无头 Chromium 当房主 →
驱动完整房间（建房 → 加入 → 开训 → 40 轮 → 判定）。

| 场景 | 验证什么 |
|---|---|
| gpu | 两端 WebGPU 协商为大模型引擎（preset=large，814,017 参数）；loss 下降；两端摘要一致 |
| refresh | 训练进行中页面刷新：主机不阻塞；手机秒收「已对齐到第 N 轮」并从下轮参与 |
| kill | 训练进行中 `am force-stop` 杀浏览器：主机检测断开、止损独自推进；手机重启 18-25s 后重连对齐，最终两端收敛 |

判定项：引擎协商 / 两端终态（`训练完成` 或晚到者的 `训练已结束`）/
清单下发 / 模型卡 loss 下降 / 两端全局权重摘要一致 / 手机零未捕获异常 /
主机日志留有掉线与重连痕迹。产物落在 `demo/screenshots/phone-*`。

跑之前先起服务：`npm run demo`（或 start-demo.cmd），5173 + 5180。
**进程归属**：服务由用户自己起最稳（脚本只读它，不杀它）。

## 4. Android / Edge 坑表（全部实测复现过）

| # | 现象 | 根因 | 做法 |
|---|---|---|---|
| 1 | 断 WiFi 后 ADB 永久 offline，`adb connect` 10060 超时 | 系统顺手关掉无线调试，旧端口不再监听 | 别断 WiFi；断开测试用 kill/refresh 场景 |
| 2 | `adb shell ...` 报 `more than one device` | 无线设备 + mDNS 条目并存 | 所有 adb 命令带 `-s <serial>` |
| 3 | `am start -d "url?a=1&b=2"` 开的标签页 URL 只有 `?a=1` | 意图 URL 在第一个 `&` 处被截断 | am start 只开**无参**页；完整 URL 用 CDP `Page.navigate` |
| 4 | force-stop 重启后旧标签页 CDP 连上就超时（Runtime.enable 都挂） | Edge 恢复的标签页是**僵尸**，只有 am start 拉起的**前台**页是活的 | 对候选页做 4s 超时探针；URL 最短的（新开的）优先试 |
| 5 | 手机页面训练中静默停更（"信令连接已断开"、永远等不到终态） | 灭屏 → Chrome 冻结页面 → WebSocket/RTC 被关 | fed 页已内置 Wake Lock；脚本侧也 `screen_off_timeout=30min` + WAKEUP |
| 6 | 被测标签页在后台：轮次时断时续、连接 failed、页面被重载 | Chrome 冻结/回收**后台**标签页 | `Page.bringToFront` 把被测页切到前台 |
| 7 | `Page.crash` 不被支持；`/json/new` 返回非 JSON | 该 Edge 版本未实现 | 用 `am force-stop` + `am start` 替代 |
| 8 | 手机侧"第 N/6 轮·已上报"后永远不动 | 慢节点末轮迟交 + 主机已收尾，节点收不到终态帧 | 见 docs/bug记录.md BUG-008；产品侧已在 finish 前广播收敛 |

## 5. 已知边界（诚实清单）

- **真·断网（飞行模式）没有自动化**：会关掉无线调试，需手动恢复后再手动重连。
  协议的「掉线止损 + 重连对齐」由 refresh/kill 两条路径覆盖。
- 手机一轮本地训练 ~8-13s，主机等待窗 12s：慢节点会偶发「本轮未上报」。
  这是设计行为（漏报不拉黑、ready 清零、如实记账本），不影响最终一致性。
- 手机 `maxBufferSize` 1 GiB：0.5B 量级模型（int4 约 438MB）在手机上临界，
  当前联调用的是 814K 参数的 large 档。
- 账本 UI 只渲染**最近一轮**明细：脚本判定「第 N 轮」行会永远等不到，
  必须看状态栏或贡献者表（脚本已按此实现）。
