## 1. 分层全景

依赖方向严格**自上而下单向**（没有反向依赖）：

```
┌──────────────────────────────────────────────────────────────────────┐
│ L7 应用层      pages/ ui/ infer/          训练台 / 联邦房间 / 推理台     │
├──────────────────────────────────────────────────────────────────────┤
│ L6 协作层      fed/ network/              联邦协议 / 去中心网络 / 公地   │
│                （09 09 10 11）              Capability / Update / 溯源   │
├──────────────────────────────────────────────────────────────────────┤
│ L5 学习层      train/ strategies/         Strategy 实现（10 类，见 07）  │
│                （07）                      产出 Update（语义无关）         │
├──────────────────────────────────────────────────────────────────────┤
│ L4 模型层      model/ + jsx/              Spec IR 构建 / 组件树 / JSX 糖  │
│                （03 04 08）                infer() 在此产出诊断           │
├──────────────────────────────────────────────────────────────────────┤
│ L3 编译层      compiler/                  infer → plan → emit            │
│                （03 06）                  融合/显存/分片/精度/通信计划       │
├──────────────────────────────────────────────────────────────────────┤
│ L2 算子层      gpu/ kernels/ ops/         op 契约 + 能力位 + WGSL 内核     │
│                （05）                      defineOp 受信逃生门             │
├──────────────────────────────────────────────────────────────────────┤
│ L1 执行层      gpu/ device/               WebGPU device / arena / batch    │
│                （06）                      多后端（WebGPU / CPU / …）        │
└──────────────────────────────────────────────────────────────────────┘
                              │
┌──────────────────────────────────────────────────────────────────────┐
│ L0 跨切面      确定性 / 可寻址 / 安全 / 观测 / 容错                     │
└──────────────────────────────────────────────────────────────────────┘
```

**特征**：每一层都只依赖下一层的**契约**，不依赖其实现。因此：
- L1 后端可换（WebGPU → CPU → WASM → 未来 WebNN）而不动 L2~L7。
- L5 策略可加（新的 Strategy）而不动 L1~L4。
- L6 网络可换（WebRTC → 中继 → 将来的 libp2p）而不动 L5。

## 2. 分层规则（六条）

| # | 规则 | 违反的后果 |
|---|---|---|
| R1 | 依赖方向单向（L_n 只 import L_k, k<n） | 形成环，编译与替换都不可能 |
| R2 | **跨层只能传 Spec IR / Update / 诊断对象 / 能力画像**（纯数据） | 传了对象引用就无法寻址、无法跨进程 |
| R3 | **能力必须被声明**：op 声明 caps，设备声明 Capability，策略声明 requires | 就是"假设同构"——本项目第一性大敌 |
| R4 | 上层不假设下层最优，只查询（`plan()` 是唯一决策点） | 上层写死策略，异构即崩 |
| R5 | 每层都要能在 Node 侧无头运行（除 L7） | 无法自动化测试与联邦无头自检 |
| R6 | 网络相关代码只在 L6，且只通过 `Transport` 接口暴露 | 传输可换，编排不动（继承既有不变量） |

## 3. 三条数据流

### 3.1 本机一次训练 step

```
trainer.step(batch)
  ├─ L4: model.forward(x, phase)      Spec IR 的实例化计算图
  ├─ L3: 已由 emit() 排好的 kernel 序列（CompileOnce-Reuse）
  ├─ L1: CommandBatch 一次 submit，arena offset 寻址
  ├─ L5: Strategy.backward(loss)      ← 反传只是这里的一个实现
  └─ L5: 应用 Update（grad → 优化器 → 新 θ）
```

### 3.2 一轮联邦训练（heterogeneous）

```
L6 node.round()
  1. negotiate       全网交换 Capability → plan() 定 同质档/异构档 + 每节点策略/角色
  2. manifest        定死 specHash / 数据集指纹 / 阶段参数 → 进指纹
  3. assign          下发 spec（内容寻址）+ 每节点执行计划
  4. ready           等齐，超时即开跑（如实少报）
  5. localPhase      每节点**按自己被分配的策略**本地训练（L5）
  6. report          上报 Update（语义因策略而异）+ 样本数
  7. verify          静态预算校验 / 共识探针复算（默认关，可开）
  8. aggregate      按 Update.kind 走不同聚合语义（见 09）
  9. broadcastBinary 背压下发新 θ
```

### 3.3 AI 生成一个新模型（AI 原生回路）

```
L4 register.query(task)  →  词汇表 + schema
L4 llm.generate(schema→受限解码)  →  Spec IR（大概率合法）
L3 infer()  →  结构化诊断  →  失败则按 fix 迭代（毫秒级，不跑 GPU）
L3 plan()   →  成本/显存/通信估计  →  超预算则改架构或改策略
L1 emit+run →  小规模对拍
L6 可选      →  fork 进公地 / 分发到集群
```

## 3.5 五条护城河（比较优势的正式表述）

> 每条护城河必须满足：**PyTorch 结构上做不到**，且**不依赖研究赌注**。
> 每条都标注了它的外部实证来源（14 章的七篇 + 一篇研究综述）与诚实边界。

| # | 护城河 | 一句话 | 外部实证 | 诚实边界 |
|---|---|---|---|---|
| **M1** | **模型即数据** | 模型是可寻址、可验证、可分发的 DAG 值 | Marin 的 Artifact 系统独立实现了同一条哈希规则；Steel-LLM 与 ZGCM-1 独立抱怨"过程不可追溯" | 可寻址 ≠ 每端最快 |
| **M2** | **AI 原生编写回路** | schema→受限解码 + 静态诊断 + 成本模型，让 agent 低成本迭代 | ZGCM-1：7 人（仅 2 人 AI 方向）+ 几百 Agent 训出 7B | 实测自主性 **L4 执行 / L2 架构**，不承诺 AI 能做研究（04 §6） |
| **M3** | **编译期智能** | infer→plan→emit，把引擎不变量从"人肉遵守"变成"编译器保证" | AXLearn 的 AOT 同一代码路径；FlexPipe 的参数化搜索 | 静态分析回答不了"会不会降"（R-23） |
| **M4** | **通用可微** | 隐式/ODE/概率/图/离散是一等原语，不是外挂库 | Steel-LLM/ZGCM 的架构变体成本 | 新算子仍需 WGSL 工作（05 §4） |
| **M5** | **训练算法无关** | 计算与学习分离；非反传策略可表达、可协作、可被选择 | ES 十亿参数级已实证；**EGGROLL 低秩 ES 达批量推理 91% 吞吐、某任务优于反传**；FF 分布式 3.75×；ZO 低内存微调 | **「参与权平等，效果不平等」**——BP 仍是生产默认；护城河是**异构参与 + 不可微系统 + 低通信结构**，不是效果更优（07 §3.2） |

**M5 的完整表述（2026 证据两次修正后）**：
PyTorch 的灵魂是 autograd，非反传方法永远是补丁。我们把计算与学习拆开，
让 ES/ZO/FF/局部规则等**可表达、可被 `plan()` 按场景选择**。

必须同时说清两句：

1. **「参与权平等，效果不平等」**：截至 2026 年，没有任何非反传方法能在
   "从头预训练超大规模 LLM"上**全面**挑战 BP（同等内存下 BP+检查点准确率高 31.1%、
   收敛快 34.8%）。所以 M5 的护城河**不是"效果更优"**。
2. **但 2026 年收窄了差距的适用范围**：ES 在**低秩扰动 + 大种群 + 只传标量**条件下
   已达十亿参数级竞争力（EGGROLL：吞吐 91% of batch inference，某任务 bits/byte
   3.40 vs 反传 3.58）。因此在**结构性优势场景**（无梯度可返、非可微/离散/低精度、
   极低通信预算、超大规模异构种群）上，ES/ZO/局部学习**不是凑合，而是更合适的工具**。

⇒ 护城河因此建立在**结构**上，而不是**研究赌注**上：
**① 异构参与**——跑不动反传的设备换个策略仍能贡献同一个 θ；
**② 不可微系统**——黑盒/离散/符号没有梯度可返，ES/ZO 是唯一选项；
**③ 低通信结构**——`perturb` 只传标量，通信量与参数量无关（07 §2.1）。
策略成熟度分级见 07 §3；完整编目见 07b。

## 4. 不变量总表（继承既有工程不变量，编号以便引用）

## 5. 与现状的映射（bridge 表）

改造不是重写。现状 → 目标的对应关系：

| 现状（`docs/架构总览.md`） | 目标层 | 迁移动作 |
|---|---|---|
| `src/gpu/device,arena,buffer,pipeline` | L1 | 保持；补多后端接口抽象 |
| `src/gpu/kernels/*.wgsl`（35 个） | L2 | 逐个包成 op，补 **caps 声明** 与契约 |
| `src/model/tiny-gpt.ts` `qwen.ts` | L4 | 原型；最终改写为 Spec IR 构建 |
| `src/train/trainer.ts` + `train/adamw` | L5 | 保留为 **Strategy=backprop 的实现**；反向逻辑逐步下沉 |
| `src/fed/protocol,node,engine,transport,bus` | L6 | 补 Capability 交换、Update 协议、聚合分支 |
| `src/tests/*`（页面 44 项 + verify:*） | L0 | 保留；新增 IR/策略/异构用例 |
| `pages/index.html` 训练台 | L7 | 保留；新增"Spec IR 模型"面板 |

**原则**：每一次迁移都必须**数值对拍一致**（同输入同输出），
禁止"顺手改一下底层"导致对拍断裂。

## 6. 本设计试图证明的核心主张

> **只要把「模型」从"运行中的对象"降维成"可寻址的数据"，
> 把「训练」从"框架宿命"分离成"可插拔策略"，
> 一批原本困难的工程问题（分发、安全、异构联邦、AI 自动建模、跨端复用）
> 会同时变得简单。**

这个主张**可被推翻**：如果层间仍需传递不可序列化的对象、
如果异构聚合在协议层表达不了、如果 AI 编写回路的成本高于手写，
则分层设计失败。这三条的验收线分别在 03、09、04。
