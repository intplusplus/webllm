# 架构总览

一篇文章讲清这个项目怎么组织的：分层、数据流、关键不变量、测试体系、已知债务。
适合新人（包括未来的自己）在第一小时建立正确的心智模型。

---

## 1. 分层全景

依赖方向严格单向（自上而下），没有反向依赖：

```
┌─ app/        页面入口 ──────────── main.ts（单机训练台）/ fed-main.ts（联邦三页）/ ir-main.ts（模型编写台）/ selftest.ts
├─ ui/         界面装配 ──────────── app.ts（训练台）/ fed-app.ts（联邦房间）/ ir-app.ts（模型编写台）
├─ ir/         Spec IR 全链路 ────── types/op/ops(47 个算子)/expr/canonical/hash/migrate
│                                    infer（静态类型与诊断）· jsx（双向投影）
│                                    plan+emit（编译层，自动 passBreak）· exec+cpu-impls（run 的 CPU 后端）
│                                    grad+cpu-grads（反向 VJP 表 + AdamW）· tinygpt-ir/train/studio
├─ fed/        公共训练网络 ──────── node.ts（编排）→ engine.ts（抽象）→ {engine.ts(mlp) | gpu-engine.ts}
│                                     transport.ts / bus.ts（WebRTC / BroadcastChannel）
├─ model/      模型图 ────────────── tiny-gpt.ts / qwen.ts（前反向 + 参数绑定）
├─ train/      训练循环 ──────────── trainer.ts（forward/backward/AdamW）
├─ infer/      推理 ──────────────── generate.ts / qwen-generate.ts
├─ weights/    权重加载 ──────────── safetensors / GPTQ int4 反量化
├─ tokenizer/  分词 ──────────────── bpe.ts
├─ store/      持久化 ────────────── IndexedDB checkpoint
├─ reference/  CPU 参考实现 ──────── 对拍基准（cpu-ref / gpt-ref / qwen-ref / ops）
└─ gpu/        WebGPU 引擎 ──────── device / arena / buffer / pipeline + kernels/（35 个 WGSL 算子）
```

三条阅读主线：

1. **训练**（单机）：ui/app.ts → model/tiny-gpt.ts → train/trainer.ts → gpu/pipeline.ts → gpu/kernels/*
2. **联邦**：ui/fed-app.ts → fed/node.ts → fed/{engine|gpu-engine}.ts → train/trainer.ts → gpu/*
3. **验证**：页面自检（app/selftest.ts → tests/）对拍 reference/（CPU 基准）；
   无头自检（scripts/verify-*.mjs）把 tests/fed/*.ts 打包进 Node 跑。

**第四条主线（IR，新）**：ui/ir-app.ts → ir/studio.ts → infer → plan → emit → exec(+cpu-impls)
→ grad(+cpu-grads)。这条线**与上面三条并存**：它把"模型"从运行中的对象降维成可寻址数据，
目标是逐步替代 1/2 两条里的手写模型与手写反向。**目前只在 CPU 参考路径上成立**
（WebGPU 后端未接、生产训练仍走 trainer.ts）。

## 2. 一次训练 step 的调用链

```
trainer.trainBatch(ids, lr)
  ├─ TinyGpt.forward(tokens)          src/model/tiny-gpt.ts
  │    └─ CommandBatch 打包多个 compute pass 一次 submit   src/gpu/pipeline.ts
  │         └─ 各 kernel 读写 arena（offset 索引，不按张量绑）
  ├─ loss = CE(softmax(logits), targets)
  ├─ TinyGpt.backward(...)            逐层反向，全部 fp32
  └─ adamw kernel 更新权重             src/gpu/kernels/misc/adamw.wgsl
```

engine 的 arena 与 CommandBatch 是两个最重要的抽象：

- **arena**：单个 kernel 最多 4 个 bind group，所以不按张量绑定，而是
  group0=权重 arena / group1=激活 arena / group2=KV 备用 / group3=uniform，
  张量用 offset 寻址。新增张量先在 arena 里分配 offset，不要改绑定布局。
- **CommandBatch**：一个 encoder 装多个 compute pass、一次 submit。
  **同一 pass 内的 dispatch 之间没有同步** —— 对同一 buffer 的 RAW/WAR/WAW 是
  未定义行为，passBreak() 必须插在每个「写→读」依赖处（BUG-001 的教训）。

## 3. 一轮联邦训练的时序

```
房主 FedNode.startHost                          src/fed/node.ts
 1. negotiateEngine(peers)    按全网能力下限选引擎（一台不支持 WebGPU → 全网 CPU）
 2. buildManifest             任务名/模型规格/超参/分片 → 指纹
 3. sendAssign                给每个 peer 下发清单（每轮开头还会重发，覆盖迟到/刷新）
 4. readyWindow               等各节点 ready，最多 10s，到点就开跑
 5. for each round:
      broadcast round/open
      localPhase              本地训练（有 2.5s 预算，跑不完如实少报样本数）
      等待上报（12s 超时；漏报只计数不拉黑，MAX_MISSES=3 才暂时不等）
      verify（默认关闭的交叉校验）
      aggregateGlobal          FedAvg / DiLoCo 共用「基准点 + 加权增量」骨架
      broadcastBinary(weights) ← 背压发送，见 BUG-008
      broadcast round/close
 6. finish → 模型卡 + 账本
```

关键不变量：

- **引擎全网一致**：`manifest.model.engine` 由主机定死后不可变（权重形状不兼容）。
- **字符表全网一致**：由房间语料唯一确定，写进 manifest 指纹；否则 logits 维度不同、无法聚合。
- **中途加入必须对齐**：新节点拿「当前全局权重」当基准（sync 帧），
  否则它的 Δ 相对随机初始权重，会**隐性污染**全局模型且账本看不出来。
- **共识探针用 1e-3 相对容差**：跨设备 WebGPU 浮点不逐位一致，不做哈希对拍。

测试代码的组织约定：`src/tests/index.ts` 汇总的两组（kernels + model）即页面自检 44 项；
`src/tests/{ops,train,infer,qwen,perf}/` 是独立测试按域分组，全部由 `model.ts` 注册；
`src/tests/fed/` 的两个文件由 scripts 经 esbuild 打包在 Node 里跑（浏览器代码 Node 跑的

`src/tests/ir/selfcheck.ts` 同理（由 `scripts/verify-ir.mjs` 打包后跑）。

## 5. 工程不变量（改代码前必读）

1. **训练全程 fp32**；f16 仅走推理，且必须先过 fp32 logits 回归对拍。
2. **无 fp32 atomicAdd**（WGSL atomic 仅整型）→ 权重梯度禁止原子累加，
   用「每输出元素唯一线程 + 规约」。
3. **2 GiB 硬顶**（`maxBufferSize` 只能降不能升）→ 多 buffer 分片 + grid 切分。
4. **同一 pass 内 dispatch 间不得存在对同一 buffer 的 RAW/WAR/WAW**（未定义行为）。
5. **RTCDataChannel 的大帧必须背压发送**：同步连发会撑爆发送队列，
   `dc.send` 队列满时**同步抛异常**（BUG-008：曾把房主循环炸断）。
6. **跨设备权重比较用容差，不用哈希**（除非同 seed 同设备逐位一致）。
7. **`Transport` 接口是编排与传输的边界**：换传输（WebRTC/BroadcastChannel/未来的中继）
   不动 `fed/node.ts` 的轮次逻辑。

## 6. 已知债务与边界（诚实清单）

| 项 | 现状 | 影响 |
|---|---|---|
| 房主单点 | 房主掉线房间即死，无迁移 | 3+ 设备 / 长时训练的可靠性瓶颈 |
| 模型规模 | 联邦训练最大 814K 参数（large 档）；0.5B 只有推理链路 | 「公共大模型」缺 LoRA 级通路（规划 M-N4） |
| 会话即弃 | 每间房从随机初始化开训，产出没有跨房间积累 | 缺公共模型仓库 + 续训（规划 M-N6） |
| 慢节点漏报 | 手机 ~8-13s/轮 vs 主机 12s 等待窗，偶发「本轮未上报」 | 设计行为（漏报不拉黑、如实记账本），但拖慢收敛 |
| 信任层 | v0 代码在（探针复算/账本/摘要），按「都是自己设备」默认关闭 | 对外开放前需启用并升级到 SHA-256 + 身份 |
| CPU 引擎在主线程 | `await sleep(0)` 让出只是止血 | 正解是 Web Worker + Comlink（file:// 单文件版需一并设计） |
| 手机显存 | `maxBufferSize` 1 GiB | 0.5B int4（438MB）± 训练激活属临界，上大模型前必须实测 |
| **IR 只有 CPU 后端** | `run()`/`backward()` 只有 `cpu-impls.ts` / `cpu-grads.ts`；`emit()` 的 arena 布局**还没变成真的 GPUBuffer + bind group** | 「浏览器里用显卡训 IR 模型」还差这一环（缺口 #1） |
| **反向未走编译器** | `plan()` 只产出 `retainActivations`/`backwardNodes` 声明；反向是 `grad.ts` 在 CPU 上按拓扑逆序跑 VJP 表 | 拿不到"反向 pass 序列 + 梯度规约"，也就没有吞吐对拍（缺口 #2） |
| **生产训练未迁 IR** | 训练台/联邦仍走手写 `model/tiny-gpt.ts` + `train/trainer.ts`；IR 版（`ir/tinygpt-ir.ts`）只在参考路径上 | IR 尚未成为唯一权威路径（12 §2 标"部分"） |
| **确定性 RNG 无消费者** | `plan()` 会分配 counter 段，但没有任何实现用它生成随机数（ES/SPSA 未实现） | INV-10 无法验证 |
| **非反传策略全缺** | P5 只做了 backprop 一刀 | 降级阶梯（手机跑 SPSA）目前只是设计 |

> 逐条对齐结论与「设计 ↔ 实现」双向清单见 [设计实现对接-2026-10-08.md](设计实现对接-2026-10-08.md)。
