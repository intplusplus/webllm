## 0. 结论先行

**工程成熟度 > 算法成熟度。** 设计稿的抽象分层（Spec IR / Learner / Update / SyncSpec）
与实现侧的不变量（fp32、背压、mid-join 对齐）都站得住；不到位的地方集中在
**聚合数学与数据科学接口**，且其中三个会让"公共模型"的核心声明失真：

| # | 问题 | 受损的设计声明 | 修订落点 |
|---|---|---|---|
| **P0-1** | 样本加权 × 异构步数 ⇒ 实际按 **n²** 加权（慢设备贡献近乎归零仍付全量上传） | "贡献计量/公平"（09 §5、11 §4） | FedNova 归一化进聚合语义（09 §5.5，ADR-015） |
| **P0-2** | 共识探针窗口永远落在某个节点的分片内 ⇒ 全局曲线对该节点非 held-out，跨节点不可比 | "可复现/可验证评估"（09 §6、11 §2.5） | 探针先切后分（INV-17，ADR-014） |
| **P0-3** | 聚合顺序 = 成员到达顺序 ⇒ 同清单两次运行得到不同 bit 位结果，"同清单→同权重"不成立 | "内容可寻址/可复现"（M1 护城河） | 规范化聚合顺序（F-INV-5，ADR-013） |

另有四个 P1（分片拓扑=连续切片即极端 non-IID；头哈希冒充内容指纹；固定等待窗在 N≥3
时被最慢设备专制；单机 demo 被能力下限谈判永久锁死在 CPU 引擎）与两个 P2
（信任层措辞强于能力；共享权重≠无隐私），全部转入风险登记册与路线图验收线。

## 1. 四个推导（可复算，作为设计决策的定量依据）

### 推导 1：通信带宽约束的完整形式

每 H 步同步一次，单步本地计算 t，上行带宽 U，fp32 全量每参数 32 bit，压缩比 r，
可容忍的通信/计算开销比 ε：

```
每步摊销通信 = 32·P·r / H  bit
约束：32·P·r / H ≤ ε·t·U   ⟹   P_max = ε·t·H·U / (32·r)
```

代入本项目实测参数（CPU 引擎 medium 档 t≈67ms/步、家庭宽带上行 U=5Mbps、ε=10%）：

| 配置 | P_max |
|---|---|
| FedAvg 每步同步（H=1, r=1） | ≈ 1K 参数 |
| DiLoCo H=100, r=1 | ≈ 105K |
| DiLoCo H=1000, r=1 | ≈ 1.0M |
| SparseLoCo（top-2%+2bit）H=200, r≈1/200 | ≈ 42M ✅ |
| SparseLoCo H=1000, r≈1/200 | ≈ 209M ✅ |

**结论**：`30M–300M` 目标区间的成立条件是 **H×r ≥ P·32/(ε·t·U)**，即必须靠
"大 H + 稀疏/量化"联合达成（DiLoCo/SparseLoCo/INTELLECT-1 的 400× 降幅正落在此）；
进入区间后瓶颈从带宽让位给 2GiB 显存与 fp32 算力。星形拓扑还要加一条 fan-out 项：
host 每轮总字节 ≈ N·4·P·r，**P 越大，host 的上行先于节点上行爆**。
→ 落点：13 开放问题⑥的默认启发式；09 §5.1 的 fan-out 约束。

### 推导 2：样本加权 × 异构步数 = n² 加权

节点 i 从共同基准 θ₀ 跑 E_i 步：Δ_i = −η·E_i·∇f_i(θ₀) + O(η²E_i²)。
样本加权聚合 Δ̄ = Σ p_iΔ_i 后，一阶项对数据分布梯度的**实际权重是 p_i·E_i 而非 p_i**；
时间预算截断 + 同 batchSize ⇒ E_i ∝ n_i ⇒ `p_iE_i ∝ n_i²`（曲率项更糟，按 n_i³）。
数值示例（PC 20 步 / 手机 4 步）：名义份额 83.3%/16.7% → 实际有效份额 96.2%/3.8%。

**修复（FedNova 归一化）**：聚合前对 Δ_i 乘 `s_i = E_ref/E_i`，`E_ref = Σp_iE_i`：

```
Σ p_i·(E_ref/E_i)·(−ηE_i∇f_i(θ₀)) = −η·E_ref·Σ p_i∇f_i(θ₀)  ✓ 回到 Σp_if_i 的正确一阶近似
```

两个附带结论：
1. **DiLoCo 的外层动量会掩盖这个问题**（对 H 内偏差不敏感）——这解释了此前实测
   "小规模下 FedAvg 优于 DiLoCo"的部分原因：两者比较时聚合语义本身不干净。
2. **同速无头测试抓不到它**（Node 里两个 FedNode 等速 ⇒ E_i 相同 ⇒ 偏差为零）。
   必须注入"模拟慢节点"做验收（FED-V9）。

### 推导 3：non-IID 的邻域半径与连续切片

FedAvg 的有效目标是 F(w)=Σp_if_i(w)；各 f_i 最优点不同时分区域收敛，半径随
异质性增长（Zhao et al. 2018 用 EMD 定量：极端 skew 掉 55%；5% 全局共享数据
挽回约 30%）。本项目的语料是戏剧拼接，**连续分片 = 教科书级极端 skew**
（不同分片的人物/韵文/旁白配比不同）。DiLoCo 的"对数据分布鲁棒"在大批量 H=500
regime 成立，不能直接搬到小批量 demo。
→ 落点：默认块交错分片 + 探针切出即 1% 共享数据 + 分片间 JS 散度上账本（11 §2.6）。

### 推导 4：固定等待窗与回合时长

PC 本地 ≈2.5s、手机完成时间 S∈U[8,13]s、窗口 W=12s：两节点时
`E[T]=max(2.5, min(S,12))≈10.4s`，与"永远等到底"几乎无差 ⇒ **两节点场景当前窗口尺寸是对的**。
但 N≥3 且只有一个慢设备时，回合被钉在 W，快设备空转：3 节点利用率 ≈ 2×2.5/(3×12) ≈ 14%。
→ 落点：quorum + grace（凑够 ⌈K/2⌉ 个 peer 上报即聚合、宽限 3s、W 仍为硬顶）；
Decoupled DiLoCo 用同一机制做到"局部故障不拖慢全局"（12）。

## 2. 已定决策（对应 design/ 新 ADR）

| ADR | 决策 | 依据 |
|---|---|---|
| **ADR-013** | 聚合必须按 **nodeId 字典序**规范化累加，与到达/重连顺序无关；模型卡 digest 作为复现凭证 | 推导 P0-3；M1 护城河需要一个稳定的可寻址输出 |
| **ADR-014** | **评测/探针窗口先于分片切出**（INV-17）；默认 **块交错分片**，禁止连续切片 | Zhao 2018 non-IID 55%/5% 共享 +30%；探针 held-out |
| **ADR-015** | 聚合语义增加 **FedNova 归一化**（Δ_i·E_ref/E_i），样本份额与有效份额**双列账本** | Wang et al. 2020 目标不一致修正；推导 2 |
| ADR-016 | 等待策略从固定窗升级为 **quorum + grace**（W 保留为硬顶），迟到更新按 staleness=1 参与下一轮（P7 异步档先行验证） | 推导 4；Decoupled DiLoCo / FedBuff |
| ADR-017 | 信任层措辞诚实化：共识探针复算 = "自报值伪造检测 + SDC 检测"；投毒检测走鲁棒聚合 + 相似度过滤，声明 Krum 的 `n≥2f+3` 边界；远期升级路径 TopLoc 激活承诺 | 09 §6 能力边界 + TopLoc 2025 |

## 4. 明确不做 / 暂缓（防范围膨胀）

- 不做拜占庭容错的密码学证明（维持工程级：探针+账本+鲁棒聚合）。
- 不引入 Secure Aggregation（2–3 台自有设备不划算；对外开放前重评）。
- 不把 TopLoc 写进承诺范围（列为 13 ⑪ 式"识别到的机会"，随信任层开放排期）。
- DNS/DP-SGD 只在贡献数据场景 + 对外开放前置条件下默认开启评估，不进 P7 主路径。
