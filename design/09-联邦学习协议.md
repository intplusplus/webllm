# 09 · 联邦学习协议

> 前置：07 学习策略层（Update 的生产者）、06 执行引擎（分片执行）、10 去中心网络。
> 定位：**本设计的主战场**。目标是让能力千差万别的设备在**互不信任**的前提下，
> 共同训练同一个模型。

---

## 1. 设计前提（三条铁律）

| # | 铁律 | 含义 |
|---|---|---|
| **F-INV-1** | 全网同 `specHash` | 结构一致是聚合的**数学前提**；不同哈希的模型**永不混聚** |
| **F-INV-2** | 本地数据不出设备 | 只传 **Update**（更新），不传样本；这是"公共网络"的信任根基 |
| **F-INV-3** | 降级不改变 specHash | 换策略/换角色/换分片仍是"同一个模型"（INV-11 的联邦版本） |
| **F-INV-5** | **聚合顺序规范化**：候选集按 `nodeId` 字典序累加，与到达/重连顺序无关 | 否则"同清单 → 逐位相同权重"的复现声明不成立，模型卡 digest 不是稳定凭证（ADR-013） |
| **F-INV-6** | **评测窗口先于分片切出**：任何节点的训练池不得包含共识探针区间 | 否则全局 loss 曲线对拥有该区间的节点不是 held-out，跨节点不可比（ADR-014） |
| **F-INV-7** | **账本必须可验追加**：每轮账本的 Merkle 根由单一权威签名并广播，历史不可静默改写 | 裸哈希链可被整体重写 ⇒ "贡献可审计"名存实亡（ADR-020，INV-20） |
| **F-INV-8** | **份额的输入必须可推导**：聚合与账本的有效份额只能由 `weightDerived`（分配 + 覆盖簿）计算，**不得直接采用节点自报的 `weight`** | 自报权重无证据约束，单节点 ×10 即可把 10% 份额抬到 52.6%（第四轮推导 16 / INV-23 / ADR-030） |

> F-INV-4（故障列表单一权威）定义在 §2，因为它挂在 Capability 协商上。
> F-INV-5/6/7 分别是"可复现 / 可评估 / 可审计"三件事在联邦侧的硬约束——
> 它们共同的数学前提是聚合为节点更新的**线性函数**（推导见评审记录第二轮推导 5~7）。
> **F-INV-8 是第四轮补的第四件事："可计量"**——份额的输入本身必须可推导，
> 否则前三件事建立在一个可被单字段操纵的基上（推导见第四轮推导 16）。

## 2. Capability 画像（异构的第一性）

> **先立一条铁律（F-INV-4）**：**故障列表必须由单一权威（聚合端/房主）判定并广播，
> 各节点不得自行判断谁掉了。** 集中式训练把这个叫"避免脑裂"——不同成员对故障列表
> 有不同看法会导致恢复流程彻底混乱（14 §11.3）。联邦场景天然有解（聚合端本就是权威），
> 但必须显式约束，否则多聚合端或房主迁移时即失控。
> 它与 §5.2 预留账本、§5.3 可调度性同属一条总原则：**集群状态必须单一真相源。**

每个节点进群时声明自己的能力——**不是声明"我有多强"，而是声明"我能做什么"**：

```
Capability := {
  device:    { kind, vendor, maxBufferSize, memAvail, dtypes, maxWorkgroup,
               supportsAtomics, supportsRNG },
  compute:   { flops: string, sustainedTflops: number },
  strategies: StrategyId[],          // **能跑**哪些学习策略（最关键）
  opCaps:    { [opRef]: OpCapability[] },   // 部分算子可能缺能力（如某端无 atomics）
  net:       { rtt, bandwidthKbps, churn, meteredData: boolean },
  role:      ('trainer'|'shard'|'evaluator'|'aggregator'|'relay')[]  // 可担任的角色
}
```

**为什么必须逐项声明**：一个"跑不了反传但内存极小"的手机，在旧设计里只能退出；
在新设计里它可以声明 `strategies: ["spsa","es","evaluator"]`，
从而以**零阶训练者**或**评估者**身份参与——**同一 θ，同样的贡献合法性**。

### 2.1 协商：同质档 vs 异构档

```
negotiate(capabilities):
  safeRequires := ∩ over peers of (peer.strategies)          // 全网公共能力
  if safeRequires ≠ ∅ and mode == 'homogeneous':
      → 全网统一用 safeStrategy（继承既有 negotiateEngine 的思路，扩展到策略）
  else if mode == 'heterogeneous':   // 需显式开启
      → 逐节点分配策略；校验 Update 语义可混（§4.3）
  else:
      → STRATEGY_INCOMPAT（拒绝或要求部分节点降级）
```

| 档 | 策略 | 收敛性 | 用途 |
|---|---|---|---|
| **同质档（默认）** | 全网取最低公共能力，**同一策略 + `barrier-round`** | **收敛到邻域**（见下 §2.1.1，不是收敛到最优点） | 生产、自检、对外演示 |
| **异构档（实验）** | 各节点各跑各策略 + **混合 sync 形态** | **研究前沿，不保证** | 探索、大规模弱设备网络 |
| **异步档（新增，实验）** | 同一策略但 `async-event` / `bounded-stale` / `gossip` | **依赖 staleness 策略；fairness 加权后可观测** | 高 churn、超低带宽、超大种群（ES） |

> **诚实标注**：异构档与异步档的收敛性是开放研究问题（见 13 开放问题③）。
> 我们只保证协议**可表达、可校验、可审计**，不提供收敛保证。默认档永远是同质档。

#### 2.1.1 同质档到底保证什么：收敛**速率**与收敛**邻域**是两件事（★ 第四轮评审，ADR-033）

"同质档 = 经典联邦收敛"这个说法在前三版里一直是**未量化**的（它听起来像"收敛到最优"）。
写成式子后，FedAvg（E 步本地、样本加权）的实际结论是
（Li et al. 2019, arXiv:1907.02189）：

```
E[F(w_T)] − F*  ≤  (2κ/(γ+T))·( B/μ + 2L‖w_0 − w*‖² ),   κ=L/μ, γ=max{8κ, E}

B = Σ_k p_k² σ_k²   +   6LΓ   +   8(E−1)² G²
    └ 噪声×参与不均衡 ┘  └ 异质性 ┘  └ 局部步数漂移 ┘
```

⇒ **正确的声明**：同质档的**速率**是 `O(1/T)`，**精度**由三项之和界定的
**邻域**决定，且后两项**不随 T 消除**：

| 邻域项 | 来源 | 对本项目的含义 |
|---|---|---|
| `Σ p_k² σ_k²` | 随机噪声 × **样本加权** | 部分参与下噪声按 `Σp²` 而非 `1/n` 收缩 ⇒ 少数大节点主导方差（**F-INV-8 的第三个理由**） |
| `6LΓ` | **数据异质性** | 房间接受度判据（下） |
| `8(E−1)² G²` | **局部步数 E 的漂移（二次）** | 时间预算截断的代价：FedNova（§5.5）修的是**加权**，这一项修的是**漂移本身**；只有 `E→1` 或 `η→0` 才消 |

**房间可接受性判据**（进 `plan()`）：11 §2.6 已要求各分片的 JS 散度上账本 ⇒
它就是 `Γ` 的可测代理。若 `6LΓ` 给出的邻域已大于探针的噪声地板（MDE，第三轮推导 13），
⇒ `plan()` 报 `ROOM_TOO_HETEROGENEOUS`（warn）并建议：缩分片 / 加共享池 / 先聚类。

> **诚实边界（Wang et al. 2022）**：用"梯度差异 Γ"是**悲观**的——真正决定收敛的是
> "**最优点处的平均漂移** `ρ = ‖G(θ*)‖`"，实测常比 Γ 小几个数量级。
> 故判据应**优先用 ρ 的实测代理**（`Probe` 在连续轮次上的损失方差不减项），
> **JS 散度只作上界兜底**——否则会把大量其实健康的房间误判为异构。

## 3. 会话生命周期（状态机）

```
JOIN → NEGOTIATE → MANIFEST → ASSIGN → READY ⇄ ROUND → FINISH
                          （异步档无 READY 屏障与 ROUND 边界，见 §3.1）

JOIN          WebRTC/中继建链；交换 Capability 画像
NEGOTIATE     plan() 定 档 + 每节点 策略/角色/分片/精度/sync 形态
MANIFEST      定死 specHash / datasetHash / 阶段参数 / 字符表 ⇒ 进指纹
               （引擎全网一致、字符表全网一致：继承既有不变量）
ASSIGN        下发 spec（内容寻址，10 §3）+ 每节点执行计划
READY          等齐（10s 上限）；到点即开跑，如实界定参与集合
ROUND {]
  broadcast round/open
  localPhase   每个节点**按自己被分配的策略**本地训练（07）
  report       上报 Update + 样本数/权重 + staleness + fairness
  verify       可选：静态预算校验 / 共识探针复算
  aggregate    按 Update.kind 分派聚合语义（§5），按 staleness 策略处理（§5.0）
  broadcastBinary 新 θ（背压发送，BUG-008）
}
FINISH         模型卡 + 账本 + 溯源链
```

### 3.1 中途加入与迟到（继承 + 扩展）

- 新节点必须拿**当前全局权重**当基准（sync 帧）——否则它的 Δ 相对随机初始权重，
  会**隐性污染**全局模型且账本看不出来（既有不变量）。
- 迟到/刷新：每轮开头**重发清单**，覆盖迟到与能力变化。
- **能力降级重分配**：某节点本轮产能下降（如切到省电模式），
  `plan()` 重算其策略/角色（INV-11：specHash 不变），而不是把它踢出。

### 3.2 异步档的状态机（★ 本版新增）

异步档**没有 ROUND 边界**，改为事件驱动：

```
JOIN → NEGOTIATE(含 sync 形态) → MANIFEST → ASSIGN → [事件循环] → FINISH

事件循环 {
  peer-ready        节点上线，拉取当前 θ（快照）
  peer-update       节点上报 Update（带 staleness / fairness / affinity）
  server-aggregate  按 staleness 策略聚合（§5.0）⇒ 新版本 θ++
  peer-pull         节点拉取新 θ（按需，不必等广播）
  peer-leave        节点掉线 ⇒ 若属某 shard ⇒ 整 shard 重分配（§5.1 原子性）
}
```

三条硬约束：
1. **故障列表由单一权威判定**（F-INV-4）——异步更容易脑裂，因为每个节点
   只看到自己视角的延迟；
2. **`baseSyncId` 必须显式**——异步下更新必然跨版本，没有基准版本就无法判断 staleness；
3. **gossip 档无聚合端** ⇒ 由 peer 两两合并，权威退化为"局部共识"，
   此时 F-INV-4 弱化为"**合并历史可追溯**"（靠溯源链事后审计）。

## 4. Update 协议（语义无关的更新）

**这是本设计最核心的接口**：让"梯度"只是多种更新中的一种。

```
Update := {
  kind:     'grad' | 'delta' | 'perturb' | 'local-delta' | 'posterior' | 'merged',
  params?:  SparseOrDense,      // delta/grad/local-delta/posterior 的参数载荷
  seed?:    RNGState,           // perturb：ES/零阶的随机种子（重建方向用）
  fitness?: number,             // perturb：该扰动的目标值
  weight:   number,             // ★ 节点**自报**的样本/token 数 ⇒ 仅 advisory（F-INV-8）
                                //   实际聚合用 weightDerived（见 §5.5.1），此字段只进诊断
  steps:    number,             // ★ 本地实际步数 E_i（FedNova 归一化必需，见 §5.5）
  method:   StrategyId,         // 产出的策略（供审计/混合判定）
  sync:     SyncSpec,           // ★ 该 peer 使用的同步形态（07 §4）
  staleness: number,            // ★ 落后全局版本数（异步核心字段）
  fairness?: number,            // ★ 新鲜度 × 参与频率的合成权重（AlignFed/AC-AFL）
  controlVariate?: SparseOrDense,  // SCAFFOLD 式漂移修正项（可选）
  efState?: SparseOrDense,      // ★ 误差反馈残差（有偏压缩的前提；第四轮 ADR-032）
                                //   所有权：残差在**客户端**、压缩快照在**服务端**，
                                //   两处都不得持有对方的真实量（INV-24）
  affinity?: number,            // ★ 与全局模型的数据亲和度（gossip 用，Chisme）
  specHash: string,             // 必须等于 manifest 的 specHash
  baseSyncId: string,           // 基于哪一版全局权重（乱序防护）
  nodeId, ts, signature?        // 溯源
}
```

### 4.0 通信语义决定聚合成本（★ 07 §2.1 的联邦面）

| `kind` | 每步通信量 | 与参数量的关系 | 聚合成本 |
|---|---|---|---|
| `perturb` | **O(1) 字节**（seed + 标量） | **无关** | **最高**：聚合端按 seed 重建方向 O(P)/条 + 合成 O(S·P) |
| `local-delta` | 本层/本块参数 | 分块线性 | 按层加权平均（只算有更新的层） |
| `delta` / `grad` | 全参数（可稀疏/量化） | 线性 | 加权平均 O(S·P) |
| `posterior` | 后验参数 | 线性 | 精度加权（矩匹配） |
| `merged` | 整模型（但**无中心**） | 线性 | 亲和度加权合并 |

⇒ **联邦友好度由 `kind` 决定，与算法数学无关**。EGGROLL 能把种群扩到百万级，
正因 `perturb` 只传标量——这是"几百个浏览器 peer 一起训"最需要的性质。
⇒ **但 `perturb` 把通信压力转成聚合端算力**（评审记录第二轮推导 8：
判定式 `S·P·4B ≤ agg_compute_budget`，不满足必须分层聚合）：
`plan()` 必须把"聚合端算力预算"与带宽预算并列检查（STR-V14）。

### 4.1 各 kind 的语义

| kind | 生产者 | 含义 | 聚合 |
|---|---|---|---|
| `grad` | backprop / reinforce / forward-mode | 真实梯度 | 加权平均 |
| `delta` | 任何策略的"参数差"形态 | Δθ | 加权平均（FedAvg 骨架） |
| `perturb` | **es / spsa / CMA-ES / EGGROLL** | 一个扰动方向 + 其 fitness | 由 `seed` 重建方向，按 fitness 加权合成 |
| `local-delta` | **local / forward-forward / PPLL** | 仅某些层的本地更新 | 加权平均（可只聚合有更新的层） |
| `posterior` | **variational** | 后验（均值/方差） | 精度加权合成（矩匹配） |
| `merged` | **gossip / 模型汤** | 已合并的模型 | **亲和度加权**合并（Chisme） |

### 4.2 为什么必须是"语义无关"的

如果 Update 只能是梯度，那么：
- 无梯度节点（黑盒/不可微）**根本无法参与**；
- 局部规则节点只能回报"我改了第 3 层"，无法用梯度语言表达；
- ES 节点的贡献是"哪个方向更好"，不是"梯度是多少"。

把 Update 语义化，等于把**学习策略的自由**从单机延伸到了集群。

### 4.3 混合兼容性（哪些 kind 可混）

```
compat(a, b) :=
  a.kind ∈ {grad, delta, local-delta} ∧ b.kind ∈ 同集合     → true   // 同族加权
  a.kind == 'perturb' ∧ b.kind == 'perturb'                 → true   // 需同 seed 空间
  a.kind == 'posterior' ∧ b.kind == 'posterior'             → true
  a.kind == 'merged'  ∧ b.kind ∈ {merged, delta}            → true   // 亲和度加权
  其余（如 grad + posterior）                                  → 需 mix policy 明确可行，否则 false
```

`false` 时：报 `UPDATE_INCOMPAT`，要求该节点降级或另起一档。
**静态可判定** ⇒ 集群不会在运行中途才发现"合并不了"。

### 4.4 压缩的前提：误差反馈（★ 第四轮评审，ADR-032 / INV-24）

§5.1.0 用 SparseLoCo（top-1~3% + 2bit）证明"大 H + 稀疏量化"能进 `30M–300M` 参数区间。
**但那条结论有一个被省略的前提**：有偏压缩器（top-k / sign）**必须带 error feedback（EF）**
才收敛——这不是调优技巧，是收敛条件（EF21, arXiv:2106.05203；Karimireddy et al. 2019）。

```
无 EF： 压缩误差 e_t = x_t − C(x_t) 独立进入更新 ⇒ E[每步] = E[g] − E[e]
        而 E[e] ≠ 0 ⇒ **固定偏置，不随 T 衰减** ⇒ 收敛到 O(‖E[e]‖) 邻域，非最优点
        （top-k 保留 1% 时，被丢弃的尾部质量可达 ‖g‖ 的百分之几 ⇒ 每步都注入）
有 EF： r_t = r_{t-1} + g_t − C(r_{t-1}+g_t)，发送 C(r_{t-1}+g_t)
        EF21 证明 r_t → 0；非凸 O(1/T)，PL 条件下**线性**
```

三条工程铁律：

1. **所有权唯一**（Zenodo 2026 的"压缩延迟动量"结论）：**残差在客户端、压缩快照在服务端**，
   两处都不得持有对方的真实量——否则量化误差会被递归回灌，**误差相乘放大**；
2. **EF 状态必须持久**（INV-24）：残差是跨轮状态，切后台/重连/快照恢复丢失即等于关掉 EF
   ⇒ 与 INV-13（快照必须含数据游标）同构，`Snapshot` 必须含压缩状态（14 §2.3）；
3. `Update.efState` 的存在**不改变 `emits` 语义**（仍是 `grad`/`delta`），
   故不破坏 INV-11（降级不改 specHash）。

> 诚实边界：EF 修的是**有偏压缩的固定偏置**，不是压缩的**方差**（那是 DIANA 系
> 无偏压缩器 + 方差缩减的活，EF-BV 把两者统一）。本设计选有偏压缩是因为它
> 在实际压缩率上更好，代价就是必须付 EF 这份工程。

## 5. 聚合语义

```
aggregate(updates):
  分组按 kind
  case grad/delta:
      // ★ FedNova 归一化（§5.5）：先按本地步数重标定，再按权重加权
      //   —— 否则时间预算截断的慢节点会被 n² 加权抹掉（同步档的异质性放大器）
      // ★ 权重来源（F-INV-8 / §5.5.1）：只用 weightDerived，**不得用自报 weight**
      s_i    := E_ref / E_i,   E_ref := Σ p_i·E_i,  p_i := weightDerived_i / Σ weightDerived
      θ ← θ + Σ p_i·s_i·Δθ_i                     // FedAvg 骨架 + 步数归一化
      // ★ 有偏压缩时先做误差反馈（§4.4）：发送 C(r+g)，本地留 r
      // ★ 规范化顺序（F-INV-5）：候选集按 nodeId 字典序累加，
      //   与到达/重连顺序无关 ⇒ 同输入必得逐位相同输出（digest 才可作复现凭证）
      // ★ 异步档再叠 fairness 合成权重（§5.0）：p_i ← p_i·freshness_i·participationPenalty_i
      // 可选：+ controlVariate_i（SCAFFOLD 式漂移修正）
  case perturb:
      // 聚合端用同一 seed 空间重建方向，按 fitness 加权
      dir_i := rng(update.seed) → δ_i
      g := −Σ (fitness_i − mean)·δ_i / (σ·n)
      // ★ EGGROLL 低秩档：dir_i 为 rank-r 矩阵扰动 ⇒ 通信仍只有 seed + 标量
  case local-delta:
      perLayer 加权平均（只聚合有该层更新的）
  case posterior:
      精度加权（信息矩阵加权平均）
  case merged:
      // 亲和度加权：吸收量 ∝ 与全局模型的数据亲和度（Chisme）
      θ ← θ + Σ α_i·(θ_i − θ)，α_i ∝ affinity_i
  然后 clip/L2 约束 + 服务端优化器（§5.6：fedavg/fedavgm/fedadam/diloco）
       + 信任规则（§5.7 的 TS 降权 / 09 §6 的其余机制）
```

可选：DiLoCo（"基准点 + 加权增量"）骨架**对全部 kind 通用**——
因为它的抽象层次就是"给一个 Δ，按权重合"，与 Δ 的来路无关。
（这一点是既有实现对异构的自然延伸。）

### 5.0 异步聚合：staleness 与 fairness（★ 本版新增，来自 2026 异步联邦研究）

**四个 staleness 策略**（07 §4.1）：

| 策略 | 聚合端行为 |
|---|---|
| `drop` | `staleness > maxLag` ⇒ 直接丢弃该 Update |
| `dampen` | 权重乘 `1/(1+λ·staleness)`，越旧越低（APFA） |
| `align` | 先用一小批**校准集**做跨版本语义对齐，再按上述加权（AlignFed） |
| `latest-all` | 每次聚合取**所有 peer 的最新可用**更新，杜绝"只合快节点的多次更新"（AC-AFL） |

**fairness 合成权重**（取代"只按样本数"）：

```
w_i = sampleWeight_i × freshness_i × participationPenalty_i
      freshness_i = 1/(1+λ_s · staleness_i)
      participationPenalty_i = 抑制"同一节点在窗口内过度贡献"（AlignFed 公平性项）
```

⇒ **这条直接防"异质性放大"**（AC-AFL 命名的失效模式）：
异步 × 非 IID ⇒ 快节点贡献更频繁 ⇒ 系统性把全局模型拉向它的数据分布。
在本项目的场景里，这就是"**最活跃的手机定义了公共模型**"——
必须靠 fairness 加权 + latest-all 挡住，否则"公共"名不副实。

> **同步档也有自己的放大器（★ 2026-10 评审新增）**：时间预算截断下
> 快节点每轮跑更多步，样本加权把慢节点按 **n²** 压掉（§5.5）——
> 这是"没有异步也会异质性放大"的形态。对策不是 fairness 加权（那是异步的），
> 而是 **FedNova 步数归一化**（§5.5，ADR-015）。两个放大器成因不同、解法不同，
> 不得合并成同一个开关。

**gossip 模式的亲和度合并**（Chisme）：无中心场景下 peer 间互相同化，
用**模型余弦相似度**推断数据亲和度，决定吸收多少——
让同质节点多合、异质节点少合，兼顾"通用知识"与"特定知识"。

> **gossip 档的共识边界（★ 第三轮评审，Boyd 式 gossip 平均，推导 11）**：
> 无中心两两合并的稳态**不是**全局均值 θ̄，而是"与混合矩阵谱隙相关"的分布：
> E‖θᵢ(t)−θ̄‖² 按混合矩阵谱隙 λ₂ 衰减、共识时间 O((1/λ₂)·log1/ε)。这意味着
> ① gossip 输出**不可称为公共模型**（各 peer 稳态互不相同）；
> ② affinity 加权**不收敛到全局目标**（只收敛到各自数据邻域的稳态）；
> ③ ⇒ 设计铁律：**gossip 档只作研究与局部池形态，公共模型产出必须过聚合端**
> （barrier/bounded-stale），gossip 仅作为其中 peer 子群内部的低层同步。

#### 5.0.1 参与偏差（participation bias）与 IPW 修正（★ 第三轮评审，推导 9）

异步/自愿参与下，每轮实际到位的是**"此刻有空且幸运"**的样本。若参与概率与
算力/数据量相关（PC 常在、手机常掉 ⇒ 强节点参与率 q_z↑），样本加权平均
系统性偏向强节点的数据分布——**这不是 staleness，是选择偏差**：

```
有偏：    E_z∼S[ p_z·∇f_z ]  −  Σ_i p_i·∇f_i   =   Σ_i (q_z(i)/q − 1)·p_i·∇f_i
修正：    w_i ← w_i / E[q_z(i)]                   （IPW，Optimal Client Sampling，
                                                    arXiv:2010.13723）
```

- **同质档（barrier-round）默认关闭 IPW**：等齐即全员参与，q≡1，偏差为零；
  迟到/掉线者按 staleness 策略处理（那是时间维，不是选择维）。
- **异步档默认开启 IPW**：`Update.weight` 旁增加 `joinProb`（本轮参与概率的
  指数衰减估计），聚合端 `p_i ← p_i·(E_ref/E_i) / joinProb_i`（FedNova 归一化之后）。
- **验收（FED-V18）**：构造"弱节点 joinProb=0.5、强节点=1"的房间 ⇒ 未 IPW 时
  全局模型向强节点数据分布漂移（探针窗口可测）；开 IPW 后漂移 ≤ 容差。

### 5.1 分片的硬约束：容量不跨后端累加（★ 来自 Marin）

Marin 联邦路由的铁律："**8 卡作业不能拆成 4+4，因为所有卡需要在同一个高速
互联域内通信**"（14 §8.3）。

⇒ 对本设计是**决定性约束**：peer 之间的 WebRTC **不是一个互联域**
（带宽差 3-4 个数量级、无集合通信原语、无共享内存）。因此：

```
允许的分片：  层切分 / 流水线（pipeline）/ 专家切分（expert parallel）
               —— 分片边界只传**激活**（一次前向），不传梯度、不做集合通信
禁止的分片：  跨 peer 的张量并行（tensor parallel）
               —— 需要每步多次 all-reduce，WebRTC 上通信占比会到 100%
```

`plan()` 遇到 `shard.plan == 'tensor'` 且分片**跨 peer** ⇒ 报 `SHARD_INFEASIBLE`，
`fix`：改为 `layer` 或 `expert`。（同一 peer 内的多 backend 仍可张量并行。）

#### 5.1.0 星形 fan-out 是带宽第一约束（★ 2026-10 评审新增）

通信预算公式（13 开放问题⑥的默认启发式）：`P_max = ε·t·H·U / (32·r)`，
其中 H=同步间隔步数、t=单步本地计算、U=上行带宽、r=压缩比、ε=可容忍开销比。
家庭宽带 5Mbps / t=67ms / ε=10% 的实测代入：

| 配置 | 可承载 P_max |
|---|---|
| FedAvg 每步同步（H=1, r=1） | ≈ 1K |
| DiLoCo H=100，全量 fp32 | ≈ 105K |
| DiLoCo H=1000，全量 fp32 | ≈ 1.0M |
| SparseLoCo（top-2%+2bit，r≈1/200）H=200 | ≈ 42M ✅ |
| 同 H、压缩下 H=1000 | ≈ 209M ✅ |

> **前提提醒（★ 第四轮评审）**：上表末两行的"稀疏 + 量化"是**有偏压缩**，
> 其可达性**以误差反馈（EF）为前提**（§4.4 / ADR-032 / INV-24）——
> 不实现 EF 直接上 top-k，会得到"通信省了、模型停在偏置邻域"的假成功。

⇒ **`30M–300M` 区间 = H·r 的联合结果**，不是"P 小"的结果。另有一条星形拓扑约束：host 每轮总字节 ≈ **N·4·P·r**（N 份广播 + N 份收齐），**P 越大 host 的上行先于节点爆**
（P=100M 全量 fp32 时一个 5Mbps host 在 30s 内连 1 个 peer 都服务不动）。
⇒ 路由决策前先过这个不等式：`N·4·P·r ≤ U_host·T_round`，不满足 ⇒ 分层聚合或
去中心聚合（gossip，10 §2），不是"先跑起来再说"。

**并且：分片与调度必须联合搜索**（★ 来自 FlexPipe）。FlexPipe 实证词表 1M 时
**最慢 stage 比最快慢 5.63×、显存多耗 4.87×**；新放置策略套预定义调度反而因新增依赖
（Embedding AllReduce）产生额外气泡，所以"放置与调度必须一起搜"。
异构联邦里更狠：手机与 PC 在同一条流水线，stage 时间差可能远超 5.63×。
⇒ `plan()` 不得"先切分再套固定调度"，必须把分片方式与调度优先级当作
**同一组自由度的不同投影**联合搜索（构造原则见 06 §2.1）。

**并且：一个 shard 的 peer 集合是原子单位**（★ 来自组级别容错）。集中式训练的结论是
"8-way TP 丢 1 卡，矩阵乘法直接无法完成"，现实路径是把整个并行组当原子单位、
组内失败就整组排除（14 §11.2）。

⇒ 本设计对应：若某 shard 由 3 个 peer 分担（层/流水线/专家分片），其中 1 个掉线，
**不能**只把掉线者的工作"分给别人"（那会改变分片拓扑 ⇒ 违反 INV-11 的 specHash
不变性），而应**整个 shard 重新分配**（换一组 peer，或降级为更少分片）。
成员变化 ⇒ 重新 `plan()`，**不打局部补丁**。

#### 5.1.0.1 shard 同伴数：可用性概率模型（★ 第三轮评审，推导 10）

"shard 是原子单位"回答了**怎么修**，没回答**配几个 peer**。设单 peer 每轮
失效率 q（浏览器场景 churn 高：切后台/省电/杀浏览器，**估计 q∈[0.05,0.3]**），
m 个 peer 的 shard 本轮可用概率：

| m（peer/shard） | q=0.05 | q=0.15 | q=0.30 |
|---|---|---|---|
| 1 | 95% | 85% | 70% |
| 2 | 90% | 72% | 49% |
| 3 | 86% | 61% | 34% |

⇒ `plan()` 的同伴数判据（进 shard 剪枝规则）：
- **单层切分/流水线 stage**：默认 m≤2；q>0.05 且该 stage 在**关键路径**时 m=1
  （原子性最廉价——掉线只少一个 stage 的 Update，不拖死拓扑）。
- **专家切分**：专家天然冗余（每 peer 持多专家），可 m=1。
- **绝不为提高吞吐把关键 shard 推到 m≥3**——边际吞吐换 49%→34% 的可用性崩塌；
  吞吐不足应改用"更多互不相交的 shard"（熵轴），不是"更胖的 shard"。
- 该表与 09 §5.1.2 冗余是一等的张力写明：**冗余买容错，不买吞吐上限**。

### 5.1.1 四层容错阶梯：联邦原生在第三层（★ 自我认知）

业界（集中式）的容错分四层，逐层成本递增（14 §11.1）：

| 层 | 集中式的做法 | 本设计的对应 |
|---|---|---|
| ① 协议/硬件自愈 | HPN 双平面、UB-Mesh 链路重试 | `Transport` 重连/重试（10 §2） |
| ② 通信库透明恢复 | VCCL **主备 RDMA 队列对**，自动切换，对上层透明（实测维持 ~76.6% 吞吐） | **主备 peer 路径**（10 §2） |
| ③ 应用层**就地恢复** | 排除故障成员、健康成员继续（难点：world_size 一致性） | **联邦的默认形态**：少一份 Update 而已 |
| ④ 全局重启恢复 | torchrun + Rendezvous + 最近 checkpoint | `Snapshot` + rejoin sync（兜底） |

⇒ 集中式框架必须用复杂工程（NCCL Shrink、组级别容错、状态冗余）才能从④爬到③；
**联邦范式天生就在③**。这不是"我们做得更好"，是**范式起点不同**——
但它是一个可以说清楚的比较优势。

### 5.1.2 冗余是一等容错手段：浏览器 peer 就是 Spot 实例

Bamboo（NSDI23）用**冗余计算**换容错，从而能用廉价 Spot 实例（14 §11.8）。
浏览器 peer 本质上**就是** Spot：随时被系统回收（切后台/省电/杀浏览器），
无法信任其持续时间。中心式云要"冗余计算 + 精妙 checkpoint"才能用 Spot；
联邦天然跑在 Spot 上。

⇒ **冗余评估/冗余计算升为一等容错手段**（而非补丁）：同一份工作可派给多个 peer，
取多数/容差一致者（共识探针的泛化，§6）；evaluator-only 角色是天然载体
（最弱设备也有用途）；07 章 ES 策略的 population 本身就是冗余。

### 5.2 预留账本：防止心跳窗口内超分配（★ 来自 Marin）

Marin 的细节：心跳 30s 一次但调度 tick 更频繁，若不记录"自上次心跳以来已分配多少"，
同一个空闲容量会在一个心跳窗口内被**反复分配** ⇒ 超分配（14 §8.3 / A.6）。

⇒ `plan()` 的集群调度必须引入预留账本：

```
effectiveCapacity(peer) = reportedAvailable − reservedSinceLastHeartbeat
每次分配后 reservedSinceLastHeartbeat += 分配量
收到新心跳 ⇒ 重置 reservedSinceLastHeartbeat
```

这把"节点**上报**的能力"与"调度器**已承诺**的能力"分开。否则协商（§3）会系统性
高估集群容量——在浏览器端（节点随时增减、能力波动大）尤其致命。

### 5.3 可调度性：不得依赖不可见的远端瞬时状态（★ 来自 FlexPipe）

FlexPipe 的 **Local Buffer**：每个 actor 把当前调度步状态写入本地缓冲、
调度步结束后统一提交，原文说这是"**用来模拟分布式环境中'同一时刻看不到远端状态'
的现实约束，保证生成的调度在真实分布式环境中可执行**"。

⇒ 本设计的对应约束：`plan()` 在聚合端生成全局执行计划，但联邦场景下
**任何时刻都没有人能看到全部 peer 的真实状态**。因此：

```
可调度性（Schedulability）：
  执行计划的每一步，只允许依赖【已确认】信息
    ——上一轮上报的能力 / 进度 / 预留（§5.2）/ 快照（14 §2.3）
  不得依赖"当前瞬时状态"（某 peer 此刻在算什么、余多少显存）
  违反者 infer()/plan() 报 SCHEDULE_UNSCHEDULABLE
```

这与预留账本是同一约束的两面：**一个防超分配，一个保可执行**。
静态可判定 ⇒ 集群不会在运行中途才发现"这计划根本跑不起来"。

### 5.4 低通信策略的实证支撑（★ FF 的分布式优势）

2026 研究综述的结论：FF 的"**优势在分布式并行，而非替代 BP**"，
且**分布式 FF 达 3.75× 加速且保持精度**（14 §12.4）。

⇒ 这把 §5 的通信预算偏好从"设计推断"升级为"有实证的路"：
FF 的层独立性 ⇒ 天然流水线并行 ⇒ 跨设备 3.75×。
**低通信策略不是"弱设备只能凑合"，而是一条本来就有独立价值的路。**

**同时必须记下规模上限**（14 §12.3）：ZO 随模型增大**更不稳定**，
因此 `spsa` 仅限小模型或小分片；**大分片上的弱设备应直接降为 evaluator-only**
（贡献前向评估/`Probe`），而不是硬上零阶。

### 5.5 聚合数学正确性：FedNova 归一化（★ 2026-10 评审新增，ADR-015）

**问题**：时间预算截断（慢设备如实少跑步数）+ 样本数加权 ⇒ 聚合伪梯度实际按
**样本量二次幂**加权。推导（节点 i 从共同基准 θ₀ 跑 E_i 步，`Δ_i = −η·E_i·∇f_i(θ₀) + O(η²E_i²)`）：

```
朴素 FedAvg：Δ̄ = Σ p_i·Δ_i ≈ −η·Σ (p_i·E_i)·∇f_i(θ₀)
  同 batchSize 且 E_i ∝ n_i  ⇒  p_i·E_i ∝ n_i²      ← 实际权重是 n²，不是 n
  二阶曲率项更糟：Σ p_i·E_i² ∝ Σ n_i³
数值示例（PC 20 步 / 手机 4 步）：名义份额 83%/17% → 有效份额 96%/3.8%
```

**后果**：慢设备的数据贡献近乎归零，却仍支付全额上传成本；"贡献计量"（11 §4）
与"公平"（§5.0）两个声明同时失真。且 DiLoCo 的外层动量大 H 下不敏感 ⇒ **掩盖问题**
（这也是小规模实测"FedAvg vs DiLoCo"结论不干净的原因之一）。

**修复（FedNova，Wang et al. 2020，arXiv:2007.07481）**：

```
聚合前对每个 Δ_i 乘 s_i = E_ref/E_i（E_ref = Σ p_i·E_i）
Σ p_i·(E_ref/E_i)·(−ηE_i∇f_i) = −η·E_ref·Σ p_i∇f_i  ✓ 回到 Σp_if_i 的一阶近似
```

三条工程约束：
1. `Update.steps`（E_i）为**必填字段**（§4），否则聚合端无从归一化；
2. 账本**双列份额**：名义样本份额 `p_i` 与归一化后有效份额 `p_i·s_i`（11 §4）——
   防止"份额显示在、实际被抹掉"的隐性失真；
3. **验收必须注入慢节点**：同速无头测试里 E_i 恒等，偏差为零，抓不到
   （FED-V9：快 20 步/慢 4 步，归一化后有效份额 == 名义份额；未归一化时比值 >5×）。

> 诚实边界：归一化只修一阶项；曲率畸变（∝n³）由 FedProx/SCAFFOLD 的
> proximal/control-variate 进一步压（P7 可选），不承诺消零。

#### 5.5.1 归一化的**输入**也必须可信：权重从分配推导（★ 第四轮评审，ADR-030 / F-INV-8）

§5.5 修好了"**步数** E_i 失真"（乘 `s_i = E_ref/E_i`），但漏了同一层的另一半：
`p_i = w_i/Σw` 里的 `w_i` 是**节点自报的样本数**（09 §4 原字段说明"自报 + 静态校验"）。
自报权重**没有任何证据约束**，而有效份额对它**线性**依赖：

```
同速（E_j≡E ⇒ s_i≡1）：  e_i(c) = c·w_i / (W_{-i} + c·w_i)
  原份额 10%  ⇒  自报样本数 ×10  ⇒  e_i = 1.0W/(0.9W+1.0W) = 52.6%
            ×100 ⇒ 91.7%   ；  ×→∞ ⇒ 100%
```

⇒ **零成本、零证据、零检测**地把 10% 的份额抬到 52.6%。后果不止份额：

- 11 §4 的三列账本（nominal/effective/probeDelta）**全部以 p_i 为基** ⇒ 三列同时失真；
- 11 §6 治理"投票权按 effective share 加权"**被同一字段夺取**；
- §5.0.1 的 IPW 修正 `w_i ← w_i/E[q_z]` 同样以自报 w_i 为基 ⇒ 一并失效；
- INV-19 修的是 `E_i` 维，**对 `w_i` 维不设防**——第一轮把 n² 修掉，却没注意 n 本身是自报的。

**修复（F-INV-8）**：权重**从已确认分配推导**——数据面本来就有且内容寻址：

```
weightDerived_i := tokens(assignedShards_i) × min(steps_i, E_max)
   来源：11 §2.6 的块表（S_i 是 dataVersion 的确定性函数，全员可算）
        + 03 §2.2 的覆盖簿（{shardId → {trained, claimedBy}}）
         + `Update.steps`（FedNova 已有字段）
   界：F-INV-2 保证数据不出本地 ⇒ 节点**不可能**训到超过 assignedShards 的 token 数
       ⇒ 权重有**可验证的上界**（下界由覆盖簿的 committed bitmap 交叉核对）
```

规则：`Update.weight`（自报）**降为 advisory**，只进诊断；自报值与推导值偏离超容差
⇒ 记 `WEIGHT_MISMATCH` 并降权（09 §6 声誉层）。**验收 FED-V21**：
自报 ×10 不得改变 effective 份额（未修实现必须挂红）。

### 5.6 服务端优化器轴：聚合 = 加权平均 + 服务端优化器（★ 2026-10 第二轮评审，ADR-018）

原设计聚合语义只有"加权平均 + clip/L2"。文献（Reddi et al. ICLR 2021 的
FedAdam/FedYogi/FedAdagrad；Hsu et al. 2019 的 FedAvgM）早已把"**服务端在聚合增量上
再跑一个优化器**"做成标准件——DiLoCo 的外层动量只是这个轴上的一个点。把这条轴显式化：

```
AggregateSpec := {
  serverOpt: 'fedavg' | 'fedavgm' | 'fedadam' | 'diloco',   // 进 manifest 指纹
  params:    { lrServer, beta, tau },                        // fedadam 的二阶矩指数衰减等
}
```

- 四档共用 §5 的归一化骨架（FedNova → 规范化顺序 → staleness/fairness 加权）；
  差异只在"Σp_iΔ_i 之后服务端做什么"：直接加（fedavg）/ 加动量（fedavgm）/
  加自适应二阶矩（fedadam）/ 外层动量大 H 下的完整 DiLoCo。
- **服务端 lr 是唯一把四档区分开的自由度**： fedavg 等价 lrServer=1、τ=1。
  账本与模型卡必须记录所用 `serverOpt` 版本（贡献分的可比性依赖它，见 R-40）。
- **验收（FED-V15）**：同一组 Update 在四种 serverOpt 下与参考实现逐一数值对拍
  （小模型、固定顺序、fp32）；DiLoCo 档与既有实现对拍不回归。

### 5.7 信任锚定：探针窗兼任 root dataset（★ FLTrust 式，ADR-018）

**问题（推导 5）**：加权平均对"放大 k 倍的单个更新"毫无防御；clip 用固定阈值
要么误伤大贡献者要么放过攻击，且不管方向。**修复**：服务端用 root dataset 从同一
θ₀ 训参考更新 Δ_s，用 ReLU(cos) 信任分重标定每个更新——

```
TS_i := ReLU( cos(Δ_i, Δ_s) ),  Δ_i ← TS_i · ‖Δ_s‖ · (Δ_i/‖Δ_i‖) · p_i
θ ← θ + Σ_i Δ_i
```

- **本项目的免费锚**：F-INV-6 切出的探针窗（全网 1% 共享数据）**就是 root dataset**——
  不新增数据管道、不破 F-INV-2。探针窗的第一个身份是 held-out 评测，第二个身份是信任锚。
- **失效模式（FoggyTrust 2026 实证，必须照抄）**：root 分布与客户分布严重不匹配时，
  诚实的 non-IID 客户也会拿低 TS ⇒ 本设计落地约束：TS **只用于异常检测与降权**
  （TS≈0 ⇒ 记入账本并逐步降权），**不把 Δ_s 方向当唯一正确方向去放大正常更新**；
  同质档默认关，仅 L2（公开房间）开启，开启时 manifest 记 `rootDatasetHash`。
- **验收（FED-V16）**：注入"×100 放大更新"与"方向相反更新"：开 TS 时全局模型 digest
  与无攻击基线一致（容差内）；未开 TS 的同一实现必须**挂红**（主导权重 > 50%）。

## 6. 防作弊（可开可关，默认维度可调）

威胁模型：恶意 peer 想要**不劳而获地影响全局模型**而不被发现。

| 层 | 手段 | 成本 | **诚实边界（2026-10 二轮评审再修订）** |
|---|---|---|---|
| **静态** | `infer()` + `plan()` 校验 Update 声明的成本是否与 spec 相符（越界即拒） | 极低 | 只挡"成本造假"，挡不住"合规的坏数据" |
| **结构** | 效应审计：`effectful` 节点的使用必须登记；无法验算外部调用 | 低 | 同上 |
| **信任锚（新增）** | `TS_i = ReLU(cos(Δ_i, Δ_s))`（§5.7，探针窗即 root dataset） | 低（一轮参考训练） | 只挡**尺度/方向异常**；抓不到"方向合理的偏斜数据"（投毒仍需鲁棒聚合 + 相似度过滤） |
| **共识探针** | 每 N 轮抽 1 节点用**同一批公开探针数据**复算，比对 θ 收敛方向（1e-3 容差，INV-7）；**必须是协议义务**（§6.2） | 中 | **只能抓两件事**：①自报值伪造（host 复算同一个 θ 的 loss）；②SDC（诚实但算错，§6.1）。**抓不到投毒**——一份在偏斜数据上认真训出来的 θ，探针 loss 完全正常 |
| **累计偏差侦探（新增）** | 对每节点的 Update 序列维护对**全局轨迹**的时间序列残差（滑窗/CUSUM），超阈值即 quarantine | 低（纯统计） | 抓"**每轮都合法、累计会漂移**"的慢速同向投毒（第四轮推导 19）；**不是**逐轮容差的替代，而是它的时间维补集（INV-26） |
| **账本** | 全量记账（贡献/被拒/降级），可事后审计；每轮 Merkle 根签名（F-INV-7） | 中 | 留痕 ≠ 裁定；裁决规则本身可被攻击（见下） |
| **声誉** | 连续异常降权/暂时排除（既有 MAX_MISSES 思路泛化） | 中 | 依赖"多数诚实"假设（**具体比例见 §6.3**） |

**信任声明的诚实边界（★ 第四轮评审，ADR-029）**：前三版写的是"不需要信任任何一台设备"，
这是**过强**的声明。任何聚合规则都存在与拜占庭比例成正比的不可消除偏好：

```
权衡下界（Yin et al. 2018）： 误差 ≥ Ω( α/√n + √d/√(nm) )
  第一项 α/√n = 拜占庭**偏置**：随 α 线性、对 n 只按 1/√n 缓降 ⇒ 不消失
trimmed-mean 精确系数：      κ* = f/(n−2f)
  n=7,f=2 ⇒ 0.67    n=10,f=2 ⇒ 0.33    n=21,f=2 ⇒ 0.12
去中心（无聚合权威）：        ByzSGD 证明需 n>3f+1，**渐近最优** ⇒ 阈值 1/3，比有聚合端更严
```

⇒ 正确的声明（替换 01/10 的原话）：

> **容忍不超过阈值比例的拜占庭节点；精度代价与拜占庭比例成正比，可量化、可记账。**
> 有聚合权威时阈值 1/2；**去中心/gossip 档阈值 1/3**（"去中心"在这里是安全性的**降低**，
> 必须写明，不能当作纯升级）。

**`plan()` 因此把"拜占庭预算"作为显式输入**：给定期望容忍 `f/n`，
由 `κ*=f/(n−2f)` 反算所需房间规模与预期精度代价——**人不能凭感觉决定房间要几个人**
（`n` 太小 ⇒ 稍微一点恶意就把邻域撑爆）。

**因此投毒/后门检测必须另走两条路**（都属于 P7+，不进当前承诺）：
1. **鲁棒聚合（必须先聚类，★ 第四轮修正）**：coordinate-wise median / trimmed mean /
   Krum 类——但 Chen et al.（NeurIPS 2020）证明 **median 型算法在"期望中位数 ≠ 期望均值"
   时根本不收敛**；实测强 non-IID 下 Krum 精度可低到 2%、CM 在攻击+偏斜下仅 12.8%
   （vs 惩罚式 F∘LS 的 89.0%）。⇒ **铁律（ADR-035）**：median/Krum **不得对全网直接跑**，
   强异构房间必须先按 affinity **聚类**，再在簇内鲁棒聚合（或改用惩罚式聚合）。
   否则"防御"在本项目最真实的场景（异构）里可能比不设防更差（R-52）。
   此外 Krum 仍要求 `n ≥ 2f+3`（**2~3 台自有设备下给不出任何保证**）；
   相似度感知过滤（H+，arXiv:2509.24330）与探针天然兼容。
2. **抽样重算 / 冗余执行**：同一 shard 派给多个 peer，取一致者（§5.1.2 冗余思想）。

**后门（backdoor）是独立威胁类，必须单列（★ 第三轮评审，ADR-027）**：
DBA（Xie et al. 2020，多恶意节点分布式植入）、Neurotoxin（ICML 2021，绕过异常
过滤器）、Chameleon（ICML 2023，自适应躲避异常检测）、Backdoored pFL
（arXiv:2307.15971）证明的失效形态是：**模型在正常输入上行为正常、在隐蔽触发器上作恶**，
全局 loss 与探针 loss 都不报警——⇒ §6 表格里"共识探针/鲁棒聚合"全部天然失明
（它们看"可用性/边界异常"，不看"条件行为异常"）。两路便宜对策：
1. **触发行为探针**（11 §2.4 `Probe.target='model'` 的 `backdoor` 原子类）：
   对每个候选发布模型跑一组"正常输入 + 微扰/罕见模板"配对，比对输出跳变幅度；
   配对差分正是 R-42 改写变体检测的同一机械（一份探针两用）。
2. **频率域防御**：FLAME（USENIX Security 2022）式"逐层范数离群 + 裁剪中值
   事后滤除"，成本与一轮 consensus probe 同阶。
⇒ 落账为 R-44：公开房间（L2）前必须至少有 ①（②随鲁棒聚合一起排期）。
验收 **FED-V20**：注入 DBA 式分布式后门 ⇒ 触发行为探针检出率 = 构造用例下 100%，
未部署探针的同一实现必须**挂红**（后门存活且全局 loss 曲线无异常）。

**升级路径（远期，开放网络前）**：
- **激活承诺代替全量复算**：TopLoc（arXiv:2501.16007）对中间激活做 LSH 承诺，
  Llama-3.1-8B 上 258 B/32 token、验证比原推理快 ~100×，且**跨 GPU/重排稳健**——
  与 INV-7 的容差故事天然一对，替代"host 复算整份权重"的重模式。
- **可复现训练挑战**：乐观可验证训练（arXiv:2403.09603）证明 fp32 跨 GPU
  **逐位复现有工程化路径**（舍入控制）——若成立，INV-7 可从"容差"升级为"可挑战"。
- **探针的对抗面（写下来防忘记）**：探针是全网公开数据 ⇒ 节点可以**只训探针窗**
  换取好看的 loss。对策即 F-INV-6（探针先切后分）+ 账本双份额（§5.5）
  + 探针双层评测（公开基准仅 advisory；内部探针 authoritative，11 §2.5）。

**隐私侧的对手文献（★ 二轮评审新增，R-39）**：聚合端天然看到每个节点的明文 Update，
而"从梯度反演训练数据"在语言模型上**已经实用化**——DAGER（NeurIPS 2024）可整批精确
恢复文本、Grab（CCS 2024）在实用训练设置下达 92.9% 恢复率、TIGER（2026）已能在
**DP 防御下**重建成功。⇒ 详见 10 §6 的分层防御与 ADR-021：本协议只负责让 Update
可被校验/可被降权；在离开 L0/L1 之前，防御在 10 而不在 09。

> 注意：**静态校验之所以可行，正是因为模型是数据**（M1）。
> PyTorch 里"宣告的成本"与"实际算的"完全无法静态比对。

### 6.1 共识探针同时是 SDC 检测器（★ 来自静默数据损坏）

集中式训练把故障分两类：**崩溃**（ Fail-Stop，好检测）与
**静默数据损坏（SDC）**——不报错、不崩溃，只是**算错了**，
比崩溃更危险（14 §11.7）。

⇒ 上表的「共识探针」此前只被当作**防作弊**（应对"恶意伪造 Update"）；
现在明确它**同时是 SDC 检测器**（应对"诚实但算错"：驱动 bug、显存位翻转、
浏览器后台降频导致的数值漂移）。一个机制同时服务三件事：

| 用途 | 面对的问题 |
|---|---|
| 防作弊 | 恶意伪造 Update |
| **SDC 检测** | 诚实但算错（静默） |
| 能力归因 | 哪项原子能力退步（11 §2.4 的 `Probe`） |

⇒ 而 ZGCM 的"loss 还在降、模型却退步"正是 SDC 类症状的**可观测表现**——
说明**只看 loss/总分发现不了它，必须靠原子能力探针**。

### 6.2 验证者困境：探针不能是"自愿"的（★ 第四轮评审，ADR-031 / INV-25）

把"共识探针"从机制语言翻成博弈语言，会撞上一条**不可能性定理**：

```
收益不等式：E[U_复算] = μ·r_eff − c   （μ=作弊比例，r_eff=抓到作弊的期望奖励，c=复算成本）
⇒ 复算 iff μ > c/r_eff  ⇒ 作弊稀少（μ→0）时**理性节点不复算** ⇒ 作弊变有利 ⇒ μ 上升 …
Zhao et al. 2024 的不可能性：当 ① 诚实证明总能通过 ② 诚实验证成本>0
⇒ **不存在**"prover 诚实 + verifier 诚实"的**纯策略 Nash 均衡**（只有混合策略均衡）
```

本设计的探针**恰好落在这个适用域**：诚实 Update 必过（容差内）、复算要在本节点重跑、
奖励只有声誉（不可转移）、被抽中概率可预测。⇒ **在对抗档（L2/L3）不能指望自愿执行**，
更不能把"没人复算"当"默认通过"（沉默默认正是困境的标准表现）。

三条修法（照抄 CTF 一脉）：

1. **义务化**：聚合端**随机指派**验证任务；被指派者不复算 ⇒ **记 miss**（既有 MAX_MISSES
   思路的泛化）——**无响应 = 记 miss，不是沉默通过**（扣留检测）；
2. **旗标（Capture-the-Flag）**：聚合端周期性在 broadcast 里**注入一个可验证的偏离**
   （如故意篡改低位的 θ、或一个"应当被检出"的合成 Update）——**诚实时也总有活干**，
   报酬从"抓到作弊"变成"接住任务"，绕开 μ→0 的困境；旗标轮的结果**必须丢弃**，
   不得污染真实模型（与 F-INV-4 单一权威配合）；
3. **PoL 的警示**：09 §6 升级路径里的"乐观可验证训练（arXiv:2403.09603）"必须标注
   **"其安全性依赖学习理论中尚未解决的问题"**——Fang et al.（arXiv:2208.03567）证明
   PoL 类"复算即验证"**已被便宜地 spoof**（跨配置可复现的攻击）。

> 诚实边界：本设计**不发币**（09 §9），所以只能靠"义务化 + 旗标"这个**无货币**版本，
> 其强度**低于**有抵押/有奖励的方案。这一点必须写出来，而不是假装探针很强。

### 6.3 慢速投毒与累计偏差（★ 第四轮评审，INV-26）

INV-7 的容差是**逐轮**的，可被"慢速同向"绕开：

```
攻击者每轮只注入 δ（‖δ‖/‖Δ_honest‖ ≤ 1e-3 − ε ⇒ 单轮永不可见）
R 轮累计：‖Σ δ_t‖ ≤ R·δ
⇒ 有效容差必须随轮数收紧：δ 独立随机 ⇒ tol/√R；δ 系统性同向 ⇒ tol/R
数值： tol=1e-3、R=1000 ⇒ 逐轮判定下攻击者可累计约 1.0（相对尺度的 100%）
```

⇒ **INV-26**：检测必须作用于**累计量**——每个节点维护对全局轨迹的时间序列残差，
用滑窗均值/方差比或 CUSUM；超阈值 ⇒ `SLOW_POISON_SUSPECT` 并 quarantine。
同一条统计量同时是 **SDC 缓慢漂移**的检测器（§6.1 的连续版）。

> 与第三轮 INV-21（评测统计）**不是同一件事**：那条管"结论是否显著"，
> 这条管"节点是否在**每轮都合法**的前提下缓慢把模型拖走"。

| FED-V7 | 通信预算 | `plan()` 在带宽约束下选低通信策略（local/forward-forward）（既有） |

| **FED-V9** | **异构步数加权正确性** | 注入慢节点（快 20 步/慢 4 步）：归一化后有效份额 == 名义样本份额；未归一化实现必须**挂红**（差值 >5×）——**同速测试不算通过**（R-33） |
| **FED-V10** | **确定性聚合** | 同清单同内容、仅打乱上报到达顺序 ⇒ 全局权重 digest **逐位一致**（F-INV-5） |
| **FED-V11** | **探针 held-out** | 静态断言：任一节点训练池 ∩ 探针窗口 = ∅（F-INV-6）；交错分片覆盖率 = 全集且互不相交 |
| **FED-V12** | **quorum+grace 回合** | 3 节点注入 1 慢设备：回合时长 ≤ 快节点本地时长 + grace，**不触顶固定窗**；慢设备更新按 staleness=1 进下一轮而非丢弃 |
| **FED-V13** | **带宽预检** | 构造 `N·4·P·r > U_host·T_round` 的房间 ⇒ `plan()` 拒绝星形路由并给出分层/去中心建议（§5.1.0） |
| **FED-V14** | **异步档 staleness 策略生效** | `bounded-stale`/`async-event` 下 fairness 加权 + latest-all 可观测：构造"快节点 + 偏斜数据"场景，全局模型不被单节点主导（STR-V10 同场景） |
| **FED-V15** | **服务端优化器轴对拍** | 同一组 Update 在 `fedavg/fedavgm/fedadam/diloco` 四档下与参考实现逐一数值对拍；DiLoCo 档不回归（§5.6） |
| **FED-V16** | **信任锚挡尺度攻击** | 注入 ×100 放大更新/方向相反更新：开 TS 时 digest 与无攻击基线一致（容差内）；同实现不开 TS 必须挂红（§5.7） |
| **FED-V17** | **账本追加日志可验** | 篡改历史账目 ⇒ Merkle 根与签名校验失败可被任意节点检出；同内容两次运行 round digest 逐位一致（F-INV-7 / ADR-020） |
| **FED-V18** | **参与偏差 IPW** | 构造"弱节点 joinProb=0.5/强节点=1"异步房：未 IPW 时全局模型向强节点分布漂移可测；开 IPW 后漂移 ≤ 容差（§5.0.1） |

| **FED-V21** | **份额输入可推导（F-INV-8）** | 构造"单节点自报样本数 ×10 / ×100"的房间：`effective` 份额**逐位不变**；未修实现（用自报 weight）必须挂红（10% → 52.6%）（§5.5.1 / ADR-030） |

## 9. 明确不做（防过度设计）

- **不做**异构学习规则混合的**收敛保证**（§2.1 已诚实标注）。
- **不做**拜占庭容错的密码学证明（共识探针 + 账本+声誉是工程级，不是密码学级）。
- **不宣称"不需要信任任何设备"**（★ 第四轮）：只说"容忍 f/n < 阈值，代价 ∝ f/n
  且可记账"；阈值与稀释界见 §6 / ADR-029。含糊其辞比给数字更损伤可信度。
- **不做**有货币的验证激励（本设计不发币）：ADR-031 的义务化 + 旗标是**无货币**版本，
  其强度**低于**有抵押/有奖励的方案——这一点是明确接受的代价，不是遗漏。
- **不做**纠删码的经济模型（不引入 Filecoin 式存储市场）：ADR-034 只要
  "有人在存 + 丢了能发现 + 缺副本能重建"三件事。
- **不做**代币/链上结算（11 的贡献账本是**数据库**，不是区块链）。
- **不承诺 Secure Aggregation**：列为 L2 开放的前置条件之一而非路线图承诺——
  它对半诚实聚合端有效、对掉线敏感，且**遮蔽个体 Update 会使投毒检测失明**
  （Meta-FL 2021 的双刃 Statement），因此与鲁棒聚合显式二选一（ADR-021）。
- **不承诺 ZK 训练证明**：VFT（2025）证明 LoRA 级可行（prover 16.8–31.2s/步、
  验证 <200ms），但联邦多方训练证明仍是开放问题，只作远期路径记录。
