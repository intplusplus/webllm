# 06 · 执行与调度引擎

> 前置：03 IR、05 算子层。
> 后置：07 学习策略层（策略感知调度）、09 联邦协议（分片执行图）。

## 1. 编译四阶段

一切执行路径固定为四步，每步**纯静态、可缓存、可复现**：

```
                    ┌──────────── replay ────────────┐
                    │                               │
Spec IR ──infer()──► 类型化图 + 诊断（秒级？不，毫秒级）
        ──plan()───► 执行计划（每节点后端/策略/分片/精度/融合/RNG/通信）
        ──emit()───► 可执行 artifact（kernel 序列 + arena 布局 + 绑定表）
        ──run()────► trace + Update（可重复执行；同一 artifact 每步复用）
```

**核心收益**：树是静态的，**一次编译、每步复用**（这正是现有
`trainer.ts` 每步重建调用的反面，也是 v2 "白送的优点"的落实）。

## 2. plan()：唯一的调度决策点

`plan()` 输入 **(IR, BackendCapability, ClusterCapability, Budget)**，
输出 **ExecutionPlan**：

```
ExecutionPlan := {
  backend: { perNode: BackendId },              // WebGPU | CPU | 未来 WebNN
  strategy: { perNode: StrategyId },            // 由 07 的选择算法产出
  role:     { perNode: Role },                  // trainer/shard/evaluator/aggregator/relay
  shard:    ShardPlan,                          // 层切分/张量切分/专家切分
  precision: { perNode, perNodeGroup },        // fp32 训练（INV-1），f16 仅推理
  fusion:   [FusionGroup],                     // 双层融合
  memory:   { arena: ArenaLayout, activations, budgetMB },  // 必须 ≤ maxBufferSize
  rng:      RNGPlan | null,                    // 策略需要时（INV-10）
  comm:     { plan: "full-delta"|"sparse"|"quant", syncEvery, maxFrameBytes },
  recompute: [NodeId]                          // 省激活的换算法
}
```

**硬约束**（plan() 必须满足，否则报错而非降级）：
arena 布局 ≤ 4 bind group/kernel、显存 ≤ 2 GiB、无 pass 内 RAW、策略 caps 相容。

### 2.1 决策空间的构造原则（★ 来自 FlexPipe：换坐标系）

FlexPipe 的元结论："关键不在于发明某一个新调度，而在于**换了一个刻画调度的
坐标系**"——把天文数字的时序空间换成"stage 放置 + 两个遍历优先级"几个自由度，
**搜索与编程同时坍缩**（1F1B 从 ~700 行降到 11 行；Tessel 逐时隙求解 8 卡即失败，
参数化后 32 卡搜索 9 分钟）。判据是它的原话：
**"空间小而稠密——里面几乎全是结构合理的调度，这是搜索开销低的根本原因。"**

⇒ 本设计 `plan()` 的决策空间必须按同一判据构造：

1. **参数化而非枚举时序**：决策表达为少数有语义的自由度
   （分片方式 / 通信策略 / 精度 / recompute / 在途 micro-batch 数），不枚举指令表。
2. **剪枝规则内置**：非法组合**搜索前**排除（"跨 peer 禁张量并行"即一条剪枝，09 §5.1）。
3. **profiling 落盘复用**：与 ENG-V1 同源；内容寻址使 profiling 结果可跨会话复用。
4. **空间必须"小而稠密"**：若大量参数组合结构非法，说明参数化选错了轴——
   这是判据，不是感觉。
5. **per-(model, input, cluster) 重新调优**：FlexPipe 证明 batch 小时 Interleaved 1F1B
   优、batch 大时 1F1B 优——**没有包打天下的调度**；内置默认值只是起点不是答案。

### 2.2 气泡填充：等待时做有用功（★ 来自 FlexPipe 梯度分离）

FlexPipe 把 Zero Bubble 泛化为"检测气泡 → 暂存非关键计算 → 插回后续气泡"，
对**任意调度**自动生效。联邦版的同构优化：等 peer 的时间就是气泡。

```
等待 peer 上报时，可填充：
  · 本地 recompute / optimizer offload（省显存）
  · Probe 评测（evaluator-only 也能贡献，07 降级阶梯末档）
  · 快照写入（L1/L2/L3，SNAP 已要求异步）
  · 下一轮 kernel 预编译（ENG-V1 编译缓存复用）
```

⇒ 直通 §7.1 的 Goodput：把"等"变成"干有用的事"。

## 3. arena 与 CommandBatch（继承现有设计）

| 概念 | 规则 |
|---|---|
| **arena** | 单 kernel 最多 4 bind group ⇒ group0=权重 / group1=激活 / group2=KV备用 / group3=uniform；张量用 offset 寻址，**新增张量先分配 offset，不改绑定布局** |
| **CommandBatch** | 一个 encoder 装多个 compute pass、一次 submit |
| **passBreak()** | 必须插在每个「写→读」依赖处；同 pass 内 dispatch 无同步（INV-2） |

**`writesReads` 依赖声明的自动化**：每个 op 声明它写/读哪些 arena 区段，
`plan()` 据此**自动插 passBreak**——把 BUG-001 的教训从"人记得"变成"机器算得出"。

## 4. 策略感知调度（本设计新增，关键）

`plan()` 读 `trainer.strategy`，排**完全不同的执行图**：

| 策略 | 排什么 | 不排什么 |
|---|---|---|
| Backprop | 前向 + 激活保留 + 反向 pass 序列 + 梯度规约 | —— |
| Forward-mode | 前向 + 切向传播（无反向 pass） | 激活保留 |
| **SPSA / 零阶** | 仅前向 ×2（或 ×1）+ 更新 | **激活、反向 pass、梯度规约** |
| **ES** | 前向 × pop + fitness 归约 | 反向、激活 |
| **局部规则 / FF** | 逐层前向 + 层内更新 | 全局反向 pass |
| EqProp | 两相位（free/nudge）前向 | 传统反向 |

**为什么这是 WebGPU 的胜利**：

| WebGPU 限制 | 非反传策略的缓解 |
|---|---|
| 2 GiB 显存上限 | 前向-only 策略**不存激活** → 上限几乎无关 |
| 无 fp32 atomicAdd | 零阶/ES 的更新在聚合端或在唯一写者路径上算 → **规约反而更简单** |
| 无多 GPU | 群体/扰动天然并行，可跨 peer 分散（09） |

> 结论：**允许非反传不是给弱设备的施舍，而是给受限平台开的正门。**

## 5. 确定性 RNG（INV-10）

需要扰动的策略（ES/SPSA/零阶/采样）必须**跨设备生成同一串随机数**，否则聚合端
无法重建方向。方案：

```
RNG := Philox4x32(key=specHash_hi32, counter=step)
// ① 算法确定（Philox 是纯整数运算，跨 GPU 厂商一致）
// ② 种子由 specHash + step 派生 ⇒ 全网同 seed
// ③ 版本化：RNG 规范进 schemaVersion ⇒ 升级不破坏历史对拍
```

规则：
- 采样/扰动**不得**用 `Date.now()`、`Math.random()`、无版本 API。
- 每个 op 声明 `rng?: { counterScope, shape }`，`plan()` 分配互不重叠的 counter 段
  （否则两个 op 用同一 counter 会互相扰动）。
- **验收（RNG-V1）**：同一 seed 在不同设备重建出**相同扰动方向**（容差内，INV-7）。

### 5.1 数据 shuffle 必须无局部结构（INV-14，来自 Marin）

**规则**：数据 shuffle / 采样 / 分片打散必须用 **counter-based 置换**
（Philox / Feistel），**禁止 LCG**。

**为什么（Marin 32B 的实证，14 §8.2）**：LCG 是线性同余发生器，
其输出**保留局部结构**——Marin 发现 GSM8k 污染数据正因 LCG shuffle 而
以"近似原文"形态存活，最终靠 Feistel 置换替换才修复。三条后果都与本设计相关：

| 若用 LCG | 后果 |
|---|---|
| 顺序保留局部结构 | 近重复样本在 batch 内相邻 ⇒ 过拟合（与 Steel-LLM 去重教训同源） |
| 污染数据以近似原文存活 | **绕过 11 §2.5 的污染检测** |
| 实现细节/周期随位宽变化 | 跨设备"同 seed 同顺序"不成立 ⇒ 违反 INV-10 |

⇒ INV-14 与 INV-10 是同一要求的一体两面：**RNG 要跨设备可复现，
置换要无局部结构**。`DataCursor.rngState` 因此必须记录**置换算法与参数版本**，
否则恢复后无法保证顺序等价。

## 6. 多后端与可移植性

| 后端 | 用途 | 优先级 |
|---|---|---|
| **WebGPU** | 主编译目标与运行时 | P1 |
| **CPU（reference）** | 对拍基准、无 GPU 设备 | P1（已有） |
| WebNN（若可用） | 复用浏览器 NPU | 远期 |
| WASM/SIMD | 极端兜底 | 远期 |

**后端可换性由 R1/R2 保证**：`emit()` 只产"调度 + 绑定表"，不绑具体 API。
同一 IR 在 Cluster 中**混合多后端**执行（PC 用 WebGPU、手机用 CPU）——
这正是异构联邦的执行基础（09）。

### 6.1 Mesh Rule：硬件差异集中在规则层（★ 来自 AXLearn）

AXLearn 的做法：**把"硬件类型"映射到一组 Config Modifier**，使平台相关优化
**集中在规则中，而不是散落到模型代码**。论文原话精确表达了本章立场：
"实现的是'**模型和训练配置不绑定硬件**'，而不是'所有硬件共享完全相同的底层 Kernel'。"

参照它的注意力后端选择：

| 硬件 | `Attn` 的后端选择 |
|---|---|
| GPU | 优先 cuDNN；稀疏/特殊场景回退 Pallas 内核 |
| Trainium | AWS Neuron Toolkit 的 NKI 内核 |
| TPU | JAX Splash Attention |
| **上层模型** | **只看到统一的 `Attn` 接口** |

⇒ 本设计的 `plan()` 就是 Mesh Rule 的一般化（同时决定后端/策略/分片/精度/RNG），
`Capability` 画像是"硬件类型"的扩展（还含策略与网络）。`plan()` 的显式输出项
**`backendRules`** 记录"哪个后端选哪个内核/布局"，使硬件差异可审计、可 diff。

**AOT 与运行同一代码路径（INV-16）**：AXLearn 让用户在单机提前分析显存与 FLOPs、
发现分片错误或 OOM，"由于 AOT 和正式训练走**同一代码路径**，本地编译通过的程序
更可能在大规模环境正常运行"。⇒ 本设计硬性要求 `infer()/plan()/emit()` 与 `run()`
共用同一套计划表示，**不允许编译期用近似模型**——否则静态结论不可信，
内容寻址缓存（Marin Artifact）也会失效。

## 7. 性能策略（从现状继承）

既有优化项（KV cache / GEMV / split-K / dispatch 合并，见
`docs/性能实测记录.md`）**全部保留**，并升级为 `plan()` 的**自动决策**：

```
plan() 按 (shape, maxBufferSize, backend) 自动选择：
  decode 相位 → GEMV + KV cache
  大输出维   → split-K
  相邻无依赖 → dispatch 合并进同 pass
显存紧张    → 开 recompute（换时间）或 optimizer offload（换主机内存）
```

**验收**：组件树/IR 实现相对手写 trainer **吞吐退化 <10%**。

### 7.1 Goodput 优先于 MFU（★ 来自 AXLearn；业界亦称 ETTR）

AXLearn 用 **Goodput**（资源真正用于**有效训练**的比例）而非 MFU 作为运行时观察指标。
对联邦场景这更关键：churn、等待上报、重连、降级重分配吃掉的都是**墙钟时间**，
MFU 高但 Goodput 低等于白跑。

```
goodput := 有效训练步时间 / 墙钟时间          // 业界同义指标：ETTR
profile() 必须同时输出 MFU 与 goodput，并按原因分解损耗：
  { waiting-for-peers, recompute, reshard, reconnect, checkpoint-io }
```

**校准基准**：集中式训练的公开基准是**优秀万卡集群 ETTR > 0.9**
（LLAMA3：16,000 GPU 约每 2.78 小时一次硬件故障，175B 模型完整 checkpoint >700 GB，
同步写入数分钟到数十分钟——这些都是 ETTR 的敌人，14 §11）。
联邦场景的 Goodput **天然更低**（等待 peer、重连、reshard 是额外损耗），
所以**损耗分解必须可归因**，否则无法判断该优化什么。

## 8. 确定性边界（诚实声明）

| 层面 | 确定性 | 说明 |
|---|---|---|
| CPU reference | **逐位一致** | 同 seed 同输入 |
| 同设备同 GPU 的 WebGPU | **逐位一致** | 同 kernel 同 arena 布局 |
| 跨设备 WebGPU | **不一致** | 驱动/workgroup 归约顺序差异 → 只做容差对拍（INV-7） |
| 跨后端（CPU vs GPU） | **不一致** | 同上 |

**设计含义**：聚合层**必须**容差；`specHash` 只保证**结构与形状**一致，
不保证数值逐位一致。这是联邦能用同结构聚合的前提，也是"内容寻址"的安全边界。

## 9. 验收线

| 编号 | 标准 |
|---|---|
| ENG-V1 | CompileOnce-Reuse：模型编译一次，N 步训练**零重复编译** |
| ENG-V2 | 自动 passBreak：对随机图，RAW 依赖全部被正确插 break（无人工标注） |
| ENG-V3 | arena/4bind-group/maxBufferSize 硬约束自动满足（构造超限用例必被拒） |
| ENG-V4 | 策略感知：前向-only 策略的调度图**不含**激活保留与反向节点 |
| ENG-V5 | RNG 跨设备一致（见 §5） |
| ENG-V6 | 吞吐退化 <10%（对比手写 trainer） |
| ENG-V7 | 多后端混合执行：CPU+WebGPU 节点跑同一模型，数值对拍容差内一致 |
| ENG-V8 | **气泡填充** | `profile()` 的 `waiting-for-peers` 损耗能被 §2.2 填充项**部分抵消**（goodput 提升可测） |
| ENG-V9 | **决策空间"小而稠密"** | 构造的参数空间中结构非法的比例 < 阈值（否则参数化选错轴） |
| ENG-V10 | **可调度性** | 生成的计划只依赖已确认信息；依赖远端瞬时状态的计划被 `SCHEDULE_UNSCHEDULABLE` 拒绝 |
