## 一句话宣言

**让整个浏览器成为 AI 的宿主；让每一个有浏览器的人，成为公共 AI 网络的一个节点。**

模型是数据不是代码，学习是可插拔策略不是框架宿命，网络默认去中心而不是中心服务器。
Web 浏览器是这一切唯一的通用入口——所以**从浏览器端做到全栈，再反向攻回主机端**。

## 术语表（全文统一用语）

| 术语 | 含义 |
|---|---|
| **Spec IR** | 模型的权威表示：可序列化、有类型、内容可寻址的**计算程序**数据 |
| **specHash** | Spec 的规范序列化哈希；全网同哈希 = 同结构 = 可聚合 |
| **infer()** | 静态分析：产出类型化图 + 结构化诊断（**不执行**） |
| **plan()** | 静态计划：产出每节点的 策略/角色/分片/精度/RNG/通信计划 |
| **emit()** | 生成可执行调度（WebGPU/CPU/分片执行图） |
| **能力位 / caps** | op 声明的可训练能力：`forward / vjp / jvp / logprob / localGrad / perturbable / invertible / nondiff` |
| **Strategy** | 学习策略：反传、ES、SPSA、局部规则、REINFORCE…的统称 |
| **Update** | 策略产出的、**与梯度语义无关**的更新（`grad/delta/perturb/local-delta/posterior`） |
| **Capability 画像** | 节点进群时声明的能力集合（设备/策略/网络/角色） |
| **降级阶梯** | 能力不足时换角色而非被抛弃：反传→前向→局部→零阶→仅评估→聚合 |
| **同质档 / 异构档** | 全网取最低公共能力（默认、可证明收敛）vs 各节点各跑各策略（研究前沿、不保证收敛） |
| **模型公地** | 可 fork / merge / 挂 adapter 的公共模型库（内容寻址） |
| **数据公地** | 带许可与溯源的公共语料库，本地不出、只传贡献 |
| **溯源链** | `parentHash / datasetHash / author` 构成的审计链 |
| **Snapshot** | 内容寻址的训练快照（round/step/adapter 三档），checkpoint 即 fork（14 §2.3） |
| **DataCursor** | 快照内的数据进度（训过哪条/哪个 epoch/RNG 状态）；只有参数的快照不合法（INV-13） |
| **DataPipelineSpec** | 声明式数据管线（算子+资源成本+可复现），"数据管线也是数据"（14 §6.3） |
| **Probe / ProbeResult** | 统一的能力/质量探针（原子能力 + 内容寻址 + 可复算），来自 ZGCM-1 的 ACE（14 §7.2） |
| **TrainingTrace** | 阶段权重 + 中间快照 + 日志 + 探针 + 条件性结论；"建造记录"是一等公地资产（14 §7.5） |
| **Skill** | 验证过的工作流/排障经验，内容寻址可复用；注册表的"经验层"（14 §7.4） |
| **Invocation Context** | 持有状态/RNG/输出集合/共享参数的上下文栈；节点不得反向持有它（INV-15）（14 §9.2） |
| **LoC-Complexity** | 接入新功能时对**既有接口**的修改量随模块数 N、变体数 M 的增长阶；本设计结构性 O(1)（14 §9.1） |
| **ETTR** | 有效训练时间比 = 实际计算时间/作业占用总时间；与本设计的 **Goodput** 同义，优秀万卡集群基准 >0.9（14 §11.9） |
| **SDC** | 静默数据损坏：不崩溃、不报错，只是算错；比崩溃更危险。共识探针即其检测器（14 §11.7） |
| **SyncSpec** | 同步性规格：barrier-round / bounded-stale / async-event / gossip / pipeline-overlap 五档，与策略平级一等（07 §4） |
| **staleness / fairness** | 异步联邦核心字段：更新落后全局的版本数；以及"新鲜度 × 参与频率"的合成权重，用于防异质性放大（09 §5.0） |
| **FedNova 归一化** | 聚合前按 `E_ref/E_i` 重标定各节点增量，修掉"样本加权 × 异构步数 ⇒ n² 加权"的聚合语义错误（09 §5.5，INV-19） |
| **双份额（nominal/effective）** | 账本同时记录名义样本份额与归一化后有效份额，防止"份额显示在、实际被抹掉"（11 §4） |
| **探针先切 / 交错分片** | 评测窗口在任何分片之前从全集移除（INV-17）；默认按块交错分片而非连续切片（11 §2.6，ADR-014） |
| **quorum + grace** | 凑够半数 peer 上报即聚合 + 短宽限，固定超时窗降为硬顶；治"N≥3 异构时回合被最慢设备专制"（13 ADR-016） |
| **信任锚 / TS** | `TS_i = ReLU(cos(Δ_i, Δ_s))`：探针窗兼任 root dataset 的 FLTrust 式信任分；只降权不放大，L2 才开（09 §5.7） |
| **serverOpt 四档** | 服务端优化器轴 `fedavg / fedavgm / fedadam / diloco`，进 manifest 指纹（09 §5.6） |
| **probeDelta** | 账本第三列贡献：探针增益 `φ_i ≈ s_i·p_i·⟨∇u, Δ_i⟩` 的一阶可复算估计（11 §4） |
| **追加日志锚点** | 每轮账本 Merkle 根由单一权威签名广播 ⇒ 历史不可静默改写（INV-20 / F-INV-7） |
| **TDA** | 训练数据归因（TracIn/TRAK/TrackStar 系）：从模型反推哪条数据影响了它；分片级坏数据定位，离线能力不进协议（14 §2.4） |
| **联邦遗忘（RTBF）** | 贡献者撤回数据的两步机制：账本回放负更新（近似）→ PEFT 模块隔离（精确）（11 §4、13 ⑲） |
| **TopLoc** | 对中间激活做 LSH 承诺的轻量训练/推理验证方案，跨 GPU 重排稳健；信任层远期升级路径而非承诺（09 §6） |
| **lowrank-bp** | GaLore 式低秩反传：SVD 投影把优化器状态压到 r×r，梯度仍是**全参数真实梯度**（`emits` 不变）；内存不足时先于 ZO/ES 尝试，投影残差超限即回退全量（07 §3.3，ADR-024） |
| **Ostrom 八原则** | 公共池资源治理的八条设计原则（Ostrom 1990）：公地开放前逐条自检，三条缺口（集体选择/分级制裁/冲突仲裁）记 L3 门票（11 §6，ADR-028） |
| **配对 CRN + MDE** | 评测判定铁律：共同随机种子的配对比较 + 最小可检测效应；探针池不足以支撑声明差异即 `EVAL_UNDERPOWERED` 拒收（11 §2.4，INV-21 / ADR-025） |
| **backdoor 触发行为探针** | `Probe.target='model'` 的 backdoor 原子类：配对差分检测"全局指标正常、带隐蔽触发器"的后门，L2 门票至少含它（11 §2.4.1，ADR-027） |
| **拜占庭预算** | `plan()` 的显式输入 `f/n`：由 `κ*=f/(n−2f)` 反算所需房间规模与预期精度代价；有聚合端阈值 1/2、去中心 1/3（13 ADR-029） |
| **weightDerived** | 权重的**唯一有效口径**：`tokens(assignedShards)×min(steps,E_max)`，来源是内容寻址的块表 + 覆盖簿；自报 `weight` 只作 advisory（09 §5.5.1，INV-23 / F-INV-8） |
| **EF 残差 / 误差反馈** | 有偏压缩器（top-k/sign）的收敛前提：残差在客户端、压缩快照在服务端，跨轮持久且随 `Snapshot` 恢复（09 §4.4，INV-24 / ADR-032） |
| **旗标（CTF）** | 聚合端周期性注入的可验证人为偏离，使"诚实时也总有活干"，绕开验证者困境的 μ→0；旗标轮结果丢弃（09 §6.2，ADR-031） |
| **累计偏差侦探** | 作用于**轨迹**而非单轮的时间序列残差检测（滑窗/CUSUM），抓"每轮都在容差内、累计漂移"的慢速投毒（09 §6.3，INV-26） |
| **收敛邻域** | 同质档的真实保证：速率 `O(1/T)`，精度由 `Σp²σ² + 6LΓ + 8(E−1)²G²` 界定，后两项不随 T 消失（09 §2.1.1，ADR-033） |
| **公地可用性** | 内容寻址 ≠ 有人存：纠删码 k-of-n + `pinningLedger` + 可用性抽样；反封闭只承诺"可举证"（11 §2.8，ADR-034） |
| **Recipe（配方）** | 产品一等对象："基座 + 数据 + 策略 + 预算 + 评测"的**可发布训练方法**；`Room` 是配方的一次执行，`Trace` 是这次执行的记录（15 §2） |
| **DataDiff（数据补丁）** | 对数据集的可寻址**变换**（不搬原文）：像代码 patch 一样可评审/可合并/可在各方本地执行；`DataPipelineSpec` 的"面向人"版本（15 §6） |
| **Proposal（提议）** | 相当于 PR：一组改动（IR/Adapter/DataDiff/配方）+ 证据（`ProbeResult`/`Trace`），过 Probe 闸门（=CI）后 merge；被拒也可 `fork-only`（15 §7） |
| **升格（Upgrade）** | 三档协作同构的实现：私人房间 → 团队 → 公开只是一次可见范围变更，不是产品重做；冷启动的关键机制（15 §3.4） |
| **契约层（Contract Layer）** | 2026 agent 协议格局中被公认空缺的一层：可移植地声明"一个 agent/资产**是什么、能做什么、受什么治理**"；本系统占这一层，通信层（MCP/A2A/AG-UI/ANP）借用不重造（16 §2.2） |
| **档位（Profile）** | 一致性档位 Core / Solo / Team / Commons：让"小实现"也有合法位置，规范分歧用档位表达而非分裂成方言（16 §5） |
| **Task（任务）** | 内容寻址的一等对象：目标 + 输入 + 产出 + **验收** + 约束 + 权责 + 血统；人机同构，可组合为函数（17 §3） |
| **验收即探针（Acceptance=Probe）** | 本设计对任务协议的分水岭：验收不是一份声明、一个人的签字，而是**内容寻址、可复算的探针**（复用 11 §2.4 的 Probe：能力原子 + CI + CRN + MDE）（17 §4） |
| **四权分离** | 定义 / 执行 / **验收** / 负责：验收者必须独立于执行者；责任不随委派转移（17 §6） |
| **角色目录（首批 9）** | 房主 / 管理员 / 聚合端 / 训练 / 评估 / 验证 / 存储 / 数据提供 / **观察者(游客)**；关键：**设备是"能力供给"，角色是"房间需求"，两者多对多**——房主 ≠ 聚合端（15 §3.5） |
| **双模（小白 / 专业）** | 同一个房间的两种深度：小白 = ≤3 个动作（一键加入 / 只看看）；专业 = 全部本地旋钮。**房主锁定项对两档都只读**（15 §3.6） |
| **TensorTable / 绑定** | 运行时张量表：IR 是纯数据、不持有任何张量（INV-15），权重/输入经节点 `props.bind` 的名字显式绑到同一张表；两节点绑同名 ⇒ 同一份张量，参数共享（tie）由此自然成立（02 §4、06 §1） |
| **VJP 表** | 反向算子的注册表（`src/ir/grad.ts` 的 `GradRegistry`），与正向 `CpuOpImpl` 表**对称**——能力必须被声明，反向不"猜每个算子的导数"（02 §2 R3、05 §3、06 §4） |
| **CompileOnce-Reuse** | 编译一次、每步复用：`infer→plan→emit` 产出的 artifact 树是静态的，`run()` 每步只换输入绑定、不重新编译（02 §3.1、06 ENG-V1） |
| **Studio（编写台）** | 模型编写台 `pages/ir.html` 的门面层（`src/ir/studio.ts`）：页面显示的每个数字都来自真实 `infer/plan/emit/run/backward`，UI 与代码行为不可能脱节（实现层，非设计稿） |

## 四条设计铁律（全文反复引用）

1. **模型是数据，不是代码。**（→ 03、10）
2. **计算与学习分离。**（→ 07、07b）
3. **异构是第一性假设，不是降级处理。**（→ 02、09）
4. **同步性也是一等维度，不是附属配置。**（→ 07 §4、09 §5.0）

## 文档与目录规范（新增设计稿请遵守）

> 目的：让文档随项目增长仍然**可检索、可追溯、不打架**。这套规范是 2026-10-08 立的。

### 目录分工（`design/` vs `docs/`）

| 目录 | 存什么 | 时态 | 命名 |
|---|---|---|---|
| `design/` | **权威设计稿**：我们要变成什么、为什么 | 目标态 | `NN-主题.md`（两位数编号） |
| `docs/` | **现状与记录**：架构总览、实测、bug、评审记录、SOP | 现在 / 过去 | 描述性中文名（如 `架构总览.md`） |

**冲突裁决**：`design/` 定义目标，`docs/` 描述现状；**冲突时以 design 为准**。
**现状债务一律登记在 `docs/`**，`design/` 只写目标（例：R-36 corpusDigest 记在 docs/评审记录）。

### 编号规则（只增不改）

- `design/NN-主题.md`：NN **只递增、不重排、不复用**（重排会让旧引用全部失效）。
- 跨文档的**稳定编号**一旦发布就不改含义：`INV-n`（不变量）、`F-INV-n`、`ADR-nnn`（决策）、
  `R-nn`（风险）、`FED-Vn`/`ENG-Vn`/`COMMONS-Vn`/`PROD-Vn`/`PROTO-Vn`/`TASK-Vn`（验收线）、
  `P①…`（产品开放问题）、`Q①…`（协议开放问题）、`T①…`（任务开放问题）。
- 实现层（IR/P0~P2）的验收号段同样**按域分配、不跳号铺张**，此处**只登记号段名、不铺开成表**：
  `IR-Vn`（编译/类型/哈希）、`OP-Vn`（算子契约）、`ENG-Vn`（引擎/调度）、
  `RUN-Vn`（run 与数值对拍）、`GRAD-Vn`（反向）、`STUDIO-Vn`（编写台）；
  由 `npm run verify:ir` 运行（另含 `ARCH/WEIGHTS`、`HASH` 等单点断言）。
- 新号段按**域**分配，不跳号铺张。

### 每次新增设计稿，必须同步更新本 README

1. 文件清单表（一行，含一句话摘要 + 状态）；
2. 文档依赖图（它消费谁、被谁消费）；
3. 阅读路线表（若面向新角色）；
4. **术语表**——任何一个新造的术语都要进表，否则全文理解会崩。

### 写作约定

- 引用外部结论必须注明**来源 + 诚实边界**（沿用设计评审三轮形成的惯例）。
- 需要对方拍板的用 **★待定**；自己没想透的用 **⚠空白**；推演而非承诺的用 **⚠推演**。
- **先加验收编号，再改正文**（对拍驱动）。

### git 管理

- 提交信息前缀：`design:`（设计稿）、`docs:`（现状文档）、`chore:`（工具/杂项）、`feat:`/`fix:`（代码）。
- 一次提交只做一类事；设计稿与代码分提交。
- 大改动先在该目录的评审记录里留推导，再改正文。
