# 设计 ↔ 实现 对接核对（2026-10-08）

> 定位：**现状记录**（放 `docs/`）。本文回答一个问题：**design/ 里的目标态与 `src/` 里的实现，
> 现在到底对得上多少？** 两个方向都要查：
> - **设计 → 实现**：设计写了、实现有没有做（缺口要如实登记，不许美化）；
> - **实现 → 设计**：实现里新出现的事实，有没有回写进设计稿（否则下一轮又要重新推导）。
>
> 做法：把 03/05 / 06/12 / 02/README 分成三组，逐条比对代码后**就地更新设计稿**，
> 本文只记结论、口径与仍未闭合的缺口。改动明细见该次 `design:` 提交。

---

## 1. 口径（先说清楚什么算"对上了"）

| 状态 | 含义 | 判定依据 |
|---|---|---|
| **有证据** | 实现里存在，且**有无头自检覆盖** | `npm run verify:ir` 里能指出具体条目 |
| **部分** | 主体存在，但缺验收或缺一半能力 | 能指出代码位置，但指不出验收条目 |
| **⚠ 未实现** | 设计写了，代码里没有 | 代码里找不到对应路径 |
| **既有** | 早于本设计就已存在（L1/L6 的老能力） | AGENTS.md 的工程不变量 |

**核心口径**：`verify:ir` 现在的 48 项是唯一的"有证据"来源。**没有验收条目的，一律不写"已完成"。**

## 3. 设计 → 实现：**未落地的缺口**（诚实清单）

按严重程度排序。每条都注明"设计在哪写的"和"为什么没有"。

| # | 缺口 | 设计出处 | 现状 |
|---|---|---|---|
| 1 | **WebGPU 后端**：arena 布局 / pass 计划**没有变成真的 GPUBuffer + bind group + WGSL pipeline** | 06 §1、§6、ENG-V7 | `run()` 只有 CPU 实现表。这是"能算"到"能用显卡算"之间唯一缺的一环 |
| 2 | **反向没有 emit 成 pass 序列**：`plan()` 只产出 `retainActivations`/`backwardNodes` 这类**声明**，真正的反向是 `grad.ts` 在 CPU 上按拓扑逆序跑 VJP 表 | 06 §4 | 设计承诺的是"反向 pass 序列 + 梯度规约"由编译器排出来；现在是解释执行 |

## 4. 实现 → 设计：本轮**回写进设计稿**的新事实

这些是"代码倒逼设计"的部分，不改设计稿的话，下一轮会有人重新踩一遍。

|---|---|
| `Model` 除根节点 `graph` 外还需要一张 **`nodes` 平铺表**（因为 `children` 是 NodeId 引用） | **03 §2**（设计缺口，已补） |

## 5. 审计过程中被**推翻**的三处判断（保留，因为它说明审计真的在查）

| 我原先的说法 | 复核结论 | 依据 |
|---|---|---|
| INV-21（CRN+MDE）"未实现" | **部分**：MDE 功效闸门已实现（池 < ⌈16/effect²⌉ 即报 `EVAL_UNDERPOWERED`），缺的是 CI 区间估计与配对 CRN | `infer.ts` 的 `INV21_COEF=16`、`EVAL_UNDERPOWERED`；IR-V2 有构造用例 |
| INV-24（有偏压缩须带 EF）"未实现" | **部分**：`COMPRESSION_WITHOUT_EF` 已实现（软判据） | `plan.ts` 的该分支 |
| ENG-V1（CompileOnce-Reuse）"有验收" | 应记 **部分**：RUN-V2 验证了"同一 artifact 复用两次逐位一致"，但**没有"零重复编译"的计数断言** | `selfcheck.ts` RUN-V2 |

> 同类修正：**ENG-V10 应记"部分（有码无验收）"**——`emit.ts` 已有 `SCHEDULE_UNSCHEDULABLE`
> 降级路径，只是没有对应验收；**P2 应限定为"CPU 路径完成"**，不是无条件"完成"。
> 另外算子计数口径应为 **34 叶 + 13 组合 = 47**（我先前口头说的"32 叶"是错的）。

## 7. 仍未闭合的三件事（下一步的候选）

1. **接 WebGPU 后端**：让 `emit()` 的 arena 变成真的 GPUBuffer，`run()` 在浏览器里用 GPU 跑
   —— 这是缺口 #1，也是"编写台里那条曲线从 CPU 变成显卡"的唯一路径。
2. **让反向也走编译器**：把 `grad.ts` 的 CPU 逆序 VJP 变成 `emit()` 排出来的反向 pass 序列
   —— 缺口 #2，做完才能谈 ENG-V6（吞吐退化 <10%）。
3. **给已有能力补验收**：ENG-V1 的"零重复编译"计数、ENG-V10 的可调度性用例
   —— 这两条代码有了、验收没有，属于"欠账不多但要说清"。
