# 08 · 家族压测

> 前置：03 IR、05 算子、07 策略。
> 目的：用**真实公开架构**反复检验抽象是否足够——这是 v2 起用有效的方法论，
> 本章是它的正式档案。每个家族：架构要点 → Spec IR 写法 → 暴露的缺口 → 吸收的设计。

---

## 1. 方法论

1. 只写**设计草图**（不写可运行代码）——压测的是**抽象**，不是实现。
2. 每个家族必须能被**上一版设计**表达，否则就是缺口，缺口必须被吸收为
   原语/能力位/策略，而不是"打个补丁"。
3. 最终要证明**闭合性**：一个小的正交原语集能生成全部家族（§5）。
4. **失败案例同样要记录**（§6）——一个从不出缺口的设计要么太泛，要么没测够。

> 若这四个无法表达，说明 IR 或策略接口仍在偷偷假设反传。

## 3. 家族细节（节选关键 8 个，其余见附录 A）

### 3.1 家族 2：DeepSeek-V4.1-Flash（相位 + 跨层 KV）

要点：552B MoE；20 层因果编码器 + 20 层解码器，**prefill 只激活 8B、decode 激活 16B**
（同一模型按相位走不同层）；CSA2 跨层复用 KV；mHC 残差；Muon+MTP。

```tsx
const V41Flash = ({ vocab, dim }) => (
  <Model trainer={{ strategy: 'backprop' }}>
    <Embed vocab={vocab} dim={dim} />
    <Memory kind="engram" />
    {ctx.phase === 'prefill'
      ? range(20).map(i => <EncLayer key={i} dim={dim} swa={i < 2} />)
      : range(20).map(i => <DecLayer key={i} dim={dim} />)}
    <Norm dim={dim} /><Head dim={dim} vocab={vocab} />
  </Model>
);
const DecLayer = ({ dim }) => (
  <>
    <Residual><Attn dim={dim} kind="global" /></Residual>
    <Residual><CrossAttn src={<Inject bus="enc-out" />} /></Residual>
    <Residual><Moe experts={384} top={6} shared={1}><FeedForward dim={dim} /></Moe></Residual>
  </>
);
```

**缺口与吸收**：① phase 是一等概念（`ctx.phase` + `annot.phase`）；
② `Bus` 把"跨层 KV 复用"从破树特例变成正交抽象（React Context 的老问题老解法）；
③ mHC 只是 `Residual` 的一种参数化（`manifold="doublyStochastic"`）。

### 3.2 家族 4：扩散 DiT（循环外置原则）

```tsx
const DiT = ({ patch, dim, layers }) => (
  <>
    <PatchEmbed patch={patch} dim={dim} />
    {range(layers).map(i => (
      <DiTBlock key={i} dim={dim}><AdaLn cond={tEmbed} /></DiTBlock>
    ))}
    <Unpatchify patch={patch} />
  </>
);
// 采样循环是**用户代码**：树只描述一步
for (const [x0, cond] of loader) {
  const loss = mse(model(addNoise(x0), t, cond), noise);
  await strategy.apply(loss);
}
```

**缺口与吸收**：`Conv` 叶 + `AdaLn/CrossAttn` 条件注入；**循环外置写成明文**——
扩散 T 步、世界模型 chunk rollout 都由用户包在外面，树只描述一步。这是特性不是限制：
train 与 sample 循环本来就该用户看得见。

### 3.3 家族 9：Neural ODE / DEQ / 可微优化（`Solve`）

```tsx
<Solve kind="ode" method="dopri5" t={[0,1]} adjoint>
  {(y, t) => <MLP dim={dim} cond={t} />}
</Solve>
<Solve kind="fixedpoint" solver="broyden" backward="implicit">
  {z => <Block dim={dim} input={z} />}
</Solve>
<Solve kind="argmin" solver="qp" backward="kkt">
  {(z) => <><Objective expr={cost(z)} /><Constraint expr={g(z)} /></>}
</Solve>
```

**缺口与吸收**：`Solve` 统一"迭代到判据 + 隐式反传"（ODE adjoint / KKT）。
v2/v3 早期完全没有这一类——这是"支持更多系统"最重要的补充。

### 3.4 家族 10：图/关系（变结构）

```tsx
<Graph edge="edge_index" reduce="sum">      {/* 结构从数据来：变长/变拓扑 */}
  {(h, e) => <MessagePass><MLP dim={dim} /></MessagePass>}
</Graph>
<Gate kind="topk" k={10} route={router}>     {/* MoE 只是它的一种路由 */}
  {experts.map((e, i) => <Expert key={i} weight={e} />)}
</Gate>
```

**缺口与吸收**：树的假设不够 → `Map`+`Gather/Scatter` 支撑变结构；
`Gate` 把动态路由正交化（MoE/条件计算/路由器共用）。新增 scatter-reduce 叶。

### 3.5 家族 14：ES 训练一个小 LM（无梯度，★ 新增）

要点：把 θ 当黑盒，采扰动 `θ+σδ_i`，按 fitness 加权更新。**完全不需要 VJP。**

```tsx
const Base = () => <GPT vocab={vocab} dim={dim} layers={4} />;
const trainer = { strategy: 'es', pop: 64, sigma: 0.02, lr: 0.01,
                  rng: 'philox', reduce: 'fitness-weighted' };
```

**缺口与吸收**：模型**可以完全不可微**（`nondiff` 节点允许出现）→ 暴露
`perturbable` 能力位与 **GPU RNG 可复现**需求。适合无梯度、大规模并行、跨异构集群。

### 3.6 家族 15：SPSA（★ 新增）

要点：2 次前向估一个（随机）方向导数；**前向-only**。

```tsx
const trainer = { strategy: 'spsa', eps: 1e-3, lr: 0.02, twoSided: true };
```

**缺口与吸收**：调度**不排激活、不排反向** → WebGPU 2 GiB 上限几乎无关。
适合显存最紧的手机。

### 3.7 家族 16：局部规则 / Forward-Forward（★ 新增）

要点：Hebbian/target-prop/DFA 用**层内信号**更新；FF 用正/负两相定义"好度"。

```tsx
{range(4).map(i => <Layer key={i} dim={dim} rule="forward-forward" />)}
// trainer = { strategy: 'forward-forward', syncEvery: 32 }
```

**缺口与吸收**：`localGrad` 能力位 + 相位 `free/nudge`；**通信极低** →
天生适合**流水线分片跨设备**（每层在自己设备上本地学）。

### 3.8 家族 17：平衡传播（★ 新增）

要点：自由相跑到平衡 + 微扰相 → 两相之差给更新；需要**可逆/能量**结构。

```tsx
<Solve kind="equilibrium" backward="contrastive" phases={['free','nudge']}>
  {x => <HopfieldBlock dim={dim} iterations={20} />}
</Solve>
```

**缺口与吸收**：`invertible` 能力位 + 双相位；把"能量模型"这类非标准架构也纳入同一框架。

## 4. 闭合性论证

给定七类计算原语（变换/组合/状态/条件/随机/循环/交互）与十类策略：

- **任意结构** = `Seq`/`Fan`/`Map`/`Bus` 的组合；
- **任意递归** = `Scan`；**任意隐式** = `Solve`；
- **任意动态结构** = `Map`+`Gather/Scatter`+`Gate`；
- **任意随机/离散** = `Sample`/`Dist`/`Discretize`；
- **任意学习规则** = 十类 Strategy 之一（或其组合 `meta`）；
- **任意部署形态** = 分片 + 多后端 + 混合策略（09）。

⇒ **没有一个家族需要"引擎特例"**。这就是"支持更多系统"的可操作定义：
不是"内置 N 个模型"，而是"**一个组合基能生成无穷个模型**"。

## 5. 压测暴露过的失败模式（记录下来，防止复发）

| 曾经的错误设计 | 被谁打穿 | 现在的做法 |
|---|---|---|
| "树就够了" | 家族 10（图）、家族 9（前向到尾部） | IR 保留显式 `wiring` |
| "双向自适应误差就够了" | 家族 2（KV 复用）、家族 4（U-Net 跳连） | `Bus` |
| "RNN 是特例" | 家族 5/6 | `Scan` 原语 |
| "模型=可微程序" | **家族 14–17（本版新增）** | 计算⊥学习（07） |
| "训练只有反传" | 同上 | Strategy 层 |
| "节点能力对等" | 家族 13 | 能力画像 + 降级阶梯（09） |
